## 2. Course Information: 강의 개요

### 2.1 강의의 목적 — 인터넷을 사용하는 수준에서 설명하는 수준으로

**자료: p.3**

강의 개요의 중심은 인터넷의 작동 원리를 **계층 모델(Layered Model)** 로 이해하고, 네트워크 기술을 설명할 수 있는 **디지털 문해력(Digital Literacy)** 을 기르는 것이다.

예를 들어 “웹사이트가 열리지 않는다”는 현상 하나에도 여러 원인이 있을 수 있다. 연결 자체가 끊겼을 수도 있고, 목적지까지의 전달이 실패했을 수도 있으며, 이름을 주소로 바꾸는 과정이나 서버의 응용 서비스에서 문제가 발생했을 수도 있다.

이때 계층 모델은 다음과 같은 질문을 할 수 있게 한다.

1. 내 장치가 가까운 네트워크에 연결되어 있는가?
2. 목적지 네트워크로 데이터를 보낼 수 있는가?
3. 상대 서비스와 통신하는 데 필요한 전송 기능이 동작하는가?
4. 요청을 받은 응용 서비스가 올바른 결과를 제공하는가?

**보충 설명:** 이는 실제 장애를 단정하는 절차가 아니라, 복잡한 현상을 역할별로 나누어 생각하는 예시다. 강의가 강조하는 논리적 분석은 용어를 많이 아는 것뿐 아니라 **현상과 원인을 구분하여 설명하는 능력** 을 포함한다고 이해할 수 있다.

## 4. Course Layout: 계층으로 바라보는 통신

### 4.1 계층을 나누는 이유

**자료: p.7, 보충 설명 포함**

인터넷 통신에는 신호 전달, 주소 지정, 경로 선택, 데이터 전달 방식, 서비스 메시지 해석 등 서로 다른 일이 필요하다. 이 모든 일을 하나의 덩어리로 다루면 어떤 기능이 무엇에 의존하는지 설명하기 어렵다.

계층 모델에서는 각 계층이 맡은 기능을 수행하고, 아래 계층의 기능을 이용하여 위 계층에 서비스를 제공한다. 예를 들어 웹 서비스가 내용을 요청하고 응답하는 규칙과, 그 데이터를 케이블 또는 무선으로 보내는 규칙을 나눠 생각할 수 있다.

그 결과 같은 응용 서비스가 서로 다른 접속 기술 위에서 동작할 수 있고, 문제가 생겼을 때 조사할 기능을 좁힐 수 있다.

### 4.2 OSI와 TCP/IP의 대응 그림 읽기

p.7 왼쪽 그림은 OSI의 7개 층을 TCP/IP의 4개 층과 대응시킨다.

```text
OSI 7계층                     TCP/IP 4계층

7 Application   ┐
6 Presentation  ├───────────── Application
5 Session       ┘
4 Transport      ──────────── Transport
3 Network        ──────────── Internet
2 Data Link     ┐
1 Physical      ┴───────────── Network Access
```

그림 일부에는 TCP/IP의 Internet 계층을 `Network Layer`로 표시한다. 이 학습노트에서는 2장의 정리 문장과 일치하도록 **Internet 계층** 이라는 이름을 기본으로 사용한다. Network Access는 자료에 따라 Network Interface 또는 Link라는 이름으로도 나타난다.

여기서 중요한 것은 상자가 단순히 줄어든 것이 아니라 **기능을 묶는 관점이 다르다** 는 점이다. OSI의 Session과 Presentation이라는 독립 상자가 TCP/IP 그림에 없더라도, 대화 관리나 데이터 표현에 관련된 기능 자체가 사라지는 것은 아니다.

### 4.3 MAC 주소, IP 주소, Port의 역할

p.7 오른쪽 위에는 IP Address, Port Numbers, MAC Address가 함께 제시된다. 세 가지는 모두 전달 과정에 관련되지만 같은 종류의 주소가 아니다.

- **MAC 주소:** 링크에서 프레임 전달 대상을 식별할 때 쓰는 주소. 그림에서는 IP 주소와 별도의 하드웨어 식별 정보로 제시된다. `00:1A:2B:3C:4D:5E` 같은 형태가 학습용 표기 예시다.
- **IP 주소:** 네트워크 계층에서 출발지와 목적지 인터페이스를 식별하고 네트워크 간 전달에 사용하는 논리적 주소. 그림에는 `192.168.1.5`가 예시로 나온다.
- **Port 번호:** 한 호스트에서 통신할 응용 프로그램 또는 서비스를 구분하는 전송 계층의 번호. 그림에는 HTTP 80, HTTPS 443 등의 대표 예시가 있다.

**보충 설명:** IP 주소를 ‘기기 이름’, Port를 ‘사람 이름’, MAC 주소를 ‘이동 경로 전체’라고 완전히 동일시하면 오해가 생긴다. 우선 **링크의 전달 대상 / 네트워크의 목적지 / 호스트 안의 통신 대상** 을 구분하는 데 집중한다.

### 4.4 프로토콜 배치 그림의 의미

p.7 오른쪽 아래 그림에는 HTTP, FTP, DNS 등 응용 관련 이름, TCP·UDP, IP·ICMP·ARP·RARP 등이 배치되어 있다. 이는 이후 학습할 이름을 계층 지도에 놓아 보는 그림이다.

이 단계에서는 다음 세 묶음을 우선 잡는다.

1. HTTP·DNS 등: 서비스를 위한 규칙.
2. TCP·UDP: 응용 프로그램 간 데이터 전송 방식.
3. IP: 네트워크 간 패킷 전달의 중심 규칙.

ICMP는 IP 통신의 오류 보고·진단과 연결되고, ARP는 로컬 네트워크에서 IPv4 주소와 링크 주소를 연결하는 역할과 관련된다. 이 장에서는 이름과 큰 위치만 확인한다. ARP의 계층 분류는 도식마다 표현이 달라질 수 있으므로 그림의 한 칸만 보고 모든 문맥에서 같은 분류라고 단정하지 않는다. RARP와 VPN의 세부 동작은 이 PDF에 설명되어 있지 않다.

## 5. 계층별 학습을 미리 연결하기

### 5.1 Week 04 — Network Access Layer

**자료: p.8**

그림에는 컴퓨터, 스위치, `Dst MAC / Src MAC / Data`가 적힌 데이터 단위, 비트열과 파형이 나온다. 오른쪽 표는 OSI의 Data Link와 Physical이 TCP/IP의 Network Access/Link에 대응한다고 보여 준다.

그림의 메시지는 두 가지다.

1. 데이터를 가까운 연결에서 전달하기 위해 프레임(Frame)과 MAC 주소를 사용한다.
2. 프레임을 구성하는 비트는 실제 매체를 통과할 수 있는 신호로 표현되어야 한다.

`Dst`는 Destination, `Src`는 Source의 약자다. 즉 목적지·출발지의 링크 주소를 데이터와 함께 다룬다는 뜻이다. 파형은 컴퓨터 내부의 추상적인 0과 1이 실제 전달 과정에서는 물리적 신호로 표현된다는 점을 강조한다.

**보충 예시:** 노트북이 주변 네트워크 장비에 데이터를 보내는 과정을 생각한다. 유선인지 무선인지에 따라 세부 방식은 달라져도, 바로 연결된 환경에서 데이터를 전달하는 기능은 필요하다. 이 장에서는 이를 ‘가까운 한 구간의 전달’로 이해한다.

### 5.2 Week 05~07 — Internet Layer와 IP

**자료: p.9**

그림에는 출발지 `192.168.1.10`, 목적지 `172.16.0.5`, 그 사이에 여러 라우터와 화살표가 나온다. `IP Packet`, `Routing & Path Selection`이라는 문구가 핵심이다.

바로 옆 장치로 보낼 수 있다는 사실만으로 멀리 떨어진 목적지까지 도달하는 것은 아니다. 여러 네트워크를 통과하려면 목적지 IP 주소를 바탕으로 다음 전달 방향을 결정해야 한다.

- **Packet:** 네트워크 계층에서 다루는 데이터 단위.
- **Routing:** 목적지로 가기 위한 경로에 관련된 정보를 결정하는 기능.
- **전달(Forwarding, 보충 용어):** 그 정보를 이용해 실제 패킷을 다음 방향으로 보내는 동작.

그림 속 여러 화살표는 가능한 연결과 경로 선택을 표현한다. 같은 패킷을 반드시 모든 방향으로 복제한다는 뜻은 아니다. 또한 그림만으로 특정 라우팅 알고리즘이나 최단 경로 계산법이 제시되었다고 볼 수 없다.

### 5.3 Week 09~10 — Transport Layer

**자료: p.10**

TCP와 UDP가 클라이언트·서버 그림으로 대비된다. TCP 쪽에는 `SYN → SYN ACK → ACK`가, UDP 쪽에는 Request와 Response가 표시되어 있다.

TCP 쪽 화살표는 본격적인 데이터 교환 전에 연결을 설정하는 절차를 나타낸다. UDP 쪽은 TCP와 같은 연결 설정 절차 없이 데이터그램을 주고받는 모습을 단순화한 것이다.

이후 전송 계층에서는 다음 질문을 배우게 된다.

- 데이터를 어느 응용 프로그램에 전달할 것인가?
- 데이터가 사라지거나 순서가 달라지면 어떻게 처리할 것인가?
- 연결 설정과 신뢰성 기능을 제공할 것인가?

**보충 설명:** TCP는 순서 있는 신뢰성 전송을 제공하지만, UDP 자체는 같은 보장을 제공하지 않는다. 그렇다고 UDP를 쓰는 응용이 어떤 추가 기능도 구현할 수 없다는 뜻은 아니다. 또한 UDP 그림의 Response는 응용의 응답을 나타낼 수 있으며, UDP가 반드시 응답을 보내 준다는 뜻은 아니다.

이 장에서는 헤더 필드나 혼잡 제어까지 확장하지 않고, **TCP와 UDP가 서로 다른 전송 서비스를 제공한다** 는 관점을 확보한다.

### 5.4 Week 11~13 — Application Layer와 Wireshark

**자료: p.11**

그림은 OSI의 상위 세 계층을 강조하고, 웹 콘텐츠 요청·응답과 Wireshark 화면을 함께 보여 준다.

응용 계층에서는 데이터가 목적지에 도달하는 것에서 한 단계 더 나아가, **그 데이터가 서비스에서 무슨 의미인가** 를 다룬다. 예를 들어 웹 요청과 응답은 각각 어떤 동작을 요구하고 어떤 결과를 돌려주는지에 관한 약속을 가진다.

Wireshark 화면의 의미는 눈에 보이지 않던 통신을 패킷 단위로 관찰하고 계층별 정보를 확인한다는 것이다. 강의 목표인 설명 능력과 실시간 확인을 실제 관찰로 연결하는 부분이다.

**주의:** 응용 계층은 사용자가 클릭하는 프로그램 전체와 완전히 같은 말은 아니다. 프로그램은 사용자 화면, 파일 처리 등 여러 기능을 포함할 수 있고, 그중 네트워크 서비스 교환에 해당하는 기능을 계층 관점으로 구분한다.

### 5.5 Week 14~15 — 배운 계층을 실제 기술에 적용

**자료: p.12**

슬라이드는 DNS, 보안, WWW, 클라우드·영상 기기 등의 그림을 제시한다. 새로운 계층을 추가하는 그림이 아니라 기존 계층 위에 다양한 기술이 결합된다는 예고다.

- **DNS:** 사람이 사용하는 이름과 네트워크 주소를 연결한다.
- **Wi-Fi:** 장치를 무선 네트워크에 접속시키는 기술과 관련된다.
- **Cyber Security:** 통신과 시스템을 보호하는 문제를 다룬다. 보안은 한 계층에만 한정되지 않는다.
- **Cloud:** 네트워크를 통해 원격 컴퓨팅 자원을 이용하는 서비스와 연결된다.
- **Streaming:** 연속적인 미디어 전달을 서비스 요구와 전송 특성에 연결한다.
- **IoT:** 다양한 사물·장치가 네트워크의 통신 주체가 되는 상황이다.
- **Future Tech:** 배운 기본 원리로 새로운 기술을 해석하는 단계다.

위 설명은 로드맵 이해를 위한 짧은 해설이다. 각 기술의 구현 방식은 이 장의 직접적인 학습 범위가 아니다.

## 7. 헷갈리기 쉬운 포인트

### 7.1 인터넷과 웹은 같은가?

인터넷은 서로 연결된 네트워크 기반이고, 웹은 그 위에서 제공되는 서비스 중 하나다. 웹사이트를 보는 것만 인터넷 통신인 것은 아니다. 이 구분은 2장의 역사에서 TCP/IP 설계자와 WWW 창시자를 분리해 이해하는 데 필요하다.

### 7.2 IP와 TCP/IP는 같은가?

IP는 Internet Protocol이라는 개별 프로토콜이다. TCP/IP는 문맥에 따라 인터넷 프로토콜 모음이나 그 구조를 나타내는 이름이다. ‘TCP/IP 모델’을 TCP와 IP라는 두 계층만 존재한다는 뜻으로 읽으면 안 된다.

### 7.3 계층은 별도 장비 한 대씩을 뜻하는가?

아니다. 계층은 기능을 분리해 설명하는 방식이다. 하나의 컴퓨터도 여러 계층의 기능을 수행하고, 하나의 장비에 여러 역할이 결합될 수도 있다.

### 7.4 Wi-Fi에 연결되면 인터넷도 되는가?

주변 접속 장비와 연결되어 있다는 사실과, 외부 목적지까지 통신할 수 있다는 사실은 다르다. 계층별 기능을 구분해야 하는 이유를 보여 주는 예다.

### 7.5 Packet과 Frame을 지금부터 구분해야 하는가?

그렇다. 세부 구조를 암기할 필요는 없지만 Packet은 네트워크 계층, Frame은 데이터 링크 계층의 단위라는 연결은 잡아 둔다. 둘 사이의 포함 관계와 캡슐화 순서는 2장에서 자세히 학습한다.

## 8. 시험 대비 핵심과 자체 점검

### 8.1 우선 설명할 수 있어야 할 문장

- 계층 모델은 복잡한 통신 기능을 역할별로 나누어 이해하게 한다.
- TCP/IP 4계층은 Application, Transport, Internet, Network Access로 정리할 수 있다.
- OSI의 상위 3계층은 TCP/IP의 Application에, 하위 2계층은 Network Access에 대응한다.
- MAC 주소, IP 주소, Port는 서로 다른 범위의 전달 대상을 구분한다.
- 강의는 기초 개념 이후 하위 계층부터 상위 계층으로 학습을 확장한다.

### 8.2 자체 점검 문제

**문제 1.** 강의가 말하는 디지털 문해력을 네트워크 관점에서 설명하라.

**해설:** 인터넷 서비스를 이용하는 데 그치지 않고, 계층 모델을 바탕으로 통신 원리와 네트워크 기술을 설명하는 능력이다. 예를 들어 연결 문제와 서비스 문제를 구분해 질문할 수 있어야 한다.

**문제 2.** Network Access 다음에 Internet 계층을 배우는 이유를 설명하라.

**해설:** 먼저 가까운 연결에서 데이터를 전달하는 방법을 이해한 뒤, 여러 네트워크를 거쳐 목적지까지 전달하는 문제로 확장하기 때문이다.

**문제 3.** “Port 번호는 인터넷에서 목적지 네트워크를 결정한다.” — OX

**정답: X.** 목적지 네트워크를 향한 전달에는 IP 주소가 관련된다. Port는 전송 계층에서 호스트 내부의 응용 통신 대상을 구분한다.

**문제 4.** “TCP/IP 모델에 Presentation 계층이 없으므로 데이터 표현 관련 기능도 필요 없다.” — OX

**정답: X.** 독립된 계층 상자가 없다는 것과 기능이 존재하지 않는다는 것은 다르다.

**문제 5.** p.9의 여러 라우터와 화살표는 무엇을 뜻하는가?

**해설:** 목적지까지 여러 연결을 거칠 수 있고, 패킷 전달을 위해 경로와 다음 전달 방향에 관한 판단이 필요하다는 뜻이다.

**문제 6.** Wireshark 실습은 강의의 큰 목표와 어떻게 연결되는가?

**해설:** 추상적으로 배운 통신을 실제 관찰 가능한 데이터로 확인하고, 계층별 정보를 해석하는 연습으로 연결된다.

## 9. 장 마지막 총정리

이 강의의 중심 질문은 **“서로 떨어진 응용 프로그램이 어떻게 데이터를 주고받는가?”** 이다. 그 답을 한 번에 외우는 대신 역할별로 나누어 배운다.

```text
Network Access → 가까운 연결의 프레임·신호 전달
Internet       → IP를 이용한 네트워크 간 패킷 전달
Transport      → 응용 프로그램 간 전송 기능
Application    → 서비스 메시지와 의미
```

1장은 이 구조를 과목 전체의 로드맵으로 제시한다. 2장은 Node·Link·Protocol, OSI/TCP/IP, PDU와 캡슐화를 통해 그 구조를 구체화한다. 3장은 Interface·Protocol·Standardization 및 관련 용어를 통해 **서로 다른 시스템이 실제로 함께 통신할 수 있는 조건** 을 설명한다.
