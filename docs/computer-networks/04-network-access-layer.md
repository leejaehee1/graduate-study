## 0. Chapter 4 전체 흐름

이번 장의 핵심 질문은 다음과 같다.

> **여러 컴퓨터가 하나의 전송 매체를 사용할 때, 누가 언제 데이터를
> 보내고 충돌을 어떻게 처리할 것인가?**

전체 흐름은 다음과 같이 잡으면 된다.

``` text
Network Classification
        ↓
전송 거리: PAN / LAN / MAN / WAN
        ↓
Topology: Bus / Ring / Mesh / Star / Tree / Hybrid
        ↓
LAN Protocol / IEEE 802
        ↓
Data Link Layer
        ↓
┌─────────────────────┐
│ LLC - 논리적 전달    │
├─────────────────────┤
│ MAC - 매체 접근 제어 │
└─────────────────────┘
        ↓
공유 매체에서 누가 먼저 전송할 것인가?
        ↓
CSMA/CD ───── 충돌 허용 후 감지/복구
Token 방식 ── 전송 권한을 순서대로 제어
        ↓
Collision Domain / Broadcast Domain
        ↓
Hub / Switch / Router
```

# 1. Network Classification

## 1.1 전송 거리에 따른 네트워크 분류

강의자료에서는 송신자와 수신자 사이의 전송 거리(Tx-Rx)를 기준으로
네트워크를 다음과 같이 구분한다.

  구분   의미                          대략적인 범위 이해
  ------ --------------------------- --------------- ---------------------
  PAN    Personal Area Network                1\~2 m 개인 주변
  LAN    Local Area Network                 약 100 m 집, 사무실, 건물 등
  MAN    Metropolitan Area Network      약 10\~50 km 도시 규모
  WAN    Wide Area Network                   수천 km 국가·대륙 규모

### 수업 필기

-   PAN → `Personal`
-   LAN → `Local`, 한국어로는 **근거리**
-   MAN → `Metropolitan`, **도시**
-   WAN → `Wide`

### 기억법

``` text
Personal → Local → Metropolitan → Wide
개인        근거리      도시          광역
```

즉 범위가 점점 커진다고 생각하면 된다.

------------------------------------------------------------------------

# 2. Network Topology

**Topology** 는 네트워크의 노드들이 어떤 형태로 연결되어 있는지를
나타낸다.

강의자료에는 다음 6가지가 나온다.

-   Bus
-   Ring
-   Mesh
-   Star
-   Tree
-   Hybrid

## 2.1 Bus Topology

``` text
PC ─┬─ PC ─┬─ PC ─┬─ PC
    │      │      │
──────── 공용 선로 ────────
```

하나의 공용 전송 선로에 여러 노드가 연결되는 구조이다.

### 수업 필기 핵심

-   **일직선**
-   **브로드캐스팅 형태**
-   자신에게 온 데이터만 수신
-   맞지 않으면 버림
-   구조적으로 브로드캐스트와 유리
-   고장이 나면 네트워크 영향이 큼
-   Ethernet, IEEE 802.3과 연결

공유 선로로 데이터가 전달되기 때문에 여러 노드가 같은 신호를 볼 수 있다.
각 노드는 목적지 정보를 확인하여 자신에게 필요한 데이터만 받아들이고
나머지는 버린다고 이해하면 된다.

------------------------------------------------------------------------

## 2.2 Ring Topology

``` text
A ─ B
|   |
D ─ C
```

노드가 고리 형태로 연결되는 구조이다.

### 수업 필기 핵심

-   순환 구조
-   **Token 방식** 과 연결
-   공정하게 전송할 수 있음
-   순차적
-   시간이 어느 정도 예측 가능
-   토큰을 제어해야 함

핵심은 아무 노드나 마음대로 보내는 것이 아니라 **전송 권한인 Token** 을
순서대로 넘겨준다는 것이다.

------------------------------------------------------------------------

## 2.3 Mesh Topology

각 노드가 여러 노드와 직접 연결되는 구조이다.

### 수업 필기 핵심

-   다중 연결
-   `1:N`, `N:1`, `N:M`
-   하나의 노드가 여러 노드와 연결될 수 있음
-   군사 네트워크, ARPANET과 연결하여 필기

연결 경로가 많기 때문에 특정 링크에 문제가 생겨도 다른 경로를 사용할 수
있다는 구조적 특징을 이해하면 된다.

------------------------------------------------------------------------

## 2.4 Star Topology

``` text
     PC
      |
PC - 중앙장비 - PC
      |
     PC
```

모든 노드가 중앙 장비를 중심으로 연결된다.

### 수업 필기 핵심

-   중앙에 Hub 또는 Switch
-   각 포트에 노드 연결
-   중앙 장비가 죽으면 전체에 큰 영향

현대 LAN을 이해할 때 매우 중요한 구조이다.

------------------------------------------------------------------------

## 2.5 Tree Topology

계층적인 트리 구조로 노드가 연결된다.

### 수업 필기 핵심

-   위계질서
-   관리자 측면에서 관리하기 쉬움
-   인터넷 망, 아파트 단지 등의 계층적 연결을 떠올릴 수 있음

------------------------------------------------------------------------

## 2.6 Hybrid Topology

둘 이상의 토폴로지를 혼합한 형태이다.

### 수업 필기

-   **혼합**
-   큰 규모에서 여러 구조를 결합

실제 네트워크는 한 가지 토폴로지만 순수하게 사용하는 것보다 여러 구조가
결합되는 경우가 많다고 이해하면 된다.

------------------------------------------------------------------------

# 3. Network Protocol

네트워크 프로토콜은 크게 **물리적 측면** 과 **논리적 측면** 으로 나누어
생각할 수 있다.

## 3.1 물리적 측면

강의자료:

-   전송 매체
-   접속 단자
-   전송 신호 규격

즉 실제로 데이터를 어떤 매체와 신호를 이용해 전달할 것인지와 관련된다.

## 3.2 논리적 측면

강의자료:

-   데이터 형식(Frame)
-   주소 지정
-   오류 제어
-   흐름 제어
-   전송 절차

즉 물리적으로 연결된 이후 데이터를 **어떤 규칙으로 주고받을 것인가** 와
관련된다.

------------------------------------------------------------------------

# 4. LAN Protocol Standards - IEEE 802

LAN 표준과 관련해 **IEEE(Institute of Electrical and Electronics
Engineers)** 가 등장한다.

IEEE 802 계열은 LAN과 관련된 표준들을 정의한다.

강의자료의 그림에서는 데이터링크 계층이 다음과 같이 구분된다.

``` text
Data Link Layer
┌─────────────────────────┐
│ 802.2 LLC               │
├─────────────────────────┤
│ 802.1 MAC Bridging      │
├──────┬──────┬──────┬────┤
│802.3 │802.4 │802.5 │802.11
│Ether │Token │Token │Wireless
│net   │Bus   │Ring  │LAN
└──────┴──────┴──────┴────┘
Physical Layer
```

### 수업 필기 연결

-   Ethernet과 **CSMA/CD**
-   Hub, Bridge, Switch, Router의 계층적 차이
-   공정성 및 충돌 처리 방식에 대한 연결

이후 내용은 사실상 이 IEEE 802 구조를 자세히 설명하는 과정이라고 보면
된다.

------------------------------------------------------------------------

# 5. 데이터링크 계층의 이층 구조 - MAC과 LLC

IEEE 802 LAN에서는 데이터링크 계층을 다시 두 부분으로 나눈다.

``` text
Network Layer
      ↑
┌─────────────┐
│ LLC Sublayer│
├─────────────┤
│ MAC Sublayer│
└─────────────┘
      ↓
Physical Layer
```

## 5.1 왜 두 계층으로 나누는가?

강의자료의 핵심 이유는 LAN에 매우 다양한 연결 방식이 존재하기 때문이다.

-   Wi-Fi
-   Ethernet
-   Bluetooth
-   기타 유·무선 방식

### 수업 필기 핵심

**MAC** 은 실제 연결 방식과 밀접하다.

> 어떻게 보낼 것인가?\
> 유선인가? 무선인가?\
> 어떤 방식으로 매체를 사용할 것인가?

반면 **LLC** 는 그 위에서 논리적으로 데이터를 처리한다.

> 제대로 갔는가?\
> 오류는 없는가?\
> 송수신 속도 차이는 어떻게 조절할 것인가?

즉 다음처럼 기억하면 좋다.

``` text
LLC = 논리적인 데이터 전달
MAC = 실제 전송 매체에 접근하는 방법
```

------------------------------------------------------------------------

# 6. MAC Layer

**MAC(Media Access Control) 계층** 은 데이터링크 계층의 하부 계층이다.

강의자료의 핵심 표현은:

> 전송 선로의 물리적 특성을 반영하고 LAN 종류를 생성한다.

즉 여러 장치가 하나의 전송 매체를 사용할 때 **누가 언제 매체를
사용할지** 결정하는 영역이라고 이해하면 된다.

대표 방식:

-   **CSMA/CD**
-   **Token Ring**

------------------------------------------------------------------------

## 6.1 CSMA/CD

CSMA/CD는 공유 버스 방식의 Ethernet과 연결된다.

수업 필기에서 `CD`를 다음과 같이 표시했다.

> **CD = Collision Detection**

즉 충돌을 감지한다는 뜻이다.

------------------------------------------------------------------------

## 6.2 Token Ring

Token Ring은 점대점(Point-to-Point) 순환 구조를 사용하며 **Token이라는
제어 프레임** 을 순환시킨다.

### 수업 필기 핵심

-   발언권을 주는 것처럼 이해
-   Token을 가진 노드만 전송 가능
-   순서를 제어하므로 충돌을 줄일 수 있음

------------------------------------------------------------------------

# 7. LLC Layer

**LLC(Logical Link Control) 계층** 은 데이터링크 계층의 상부 계층이다.

강의자료에서는 송수신 호스트 사이의 프레임 전송 과정에서 논리적인 오류가
발생하면 이를 복구하는 작업을 담당한다고 설명한다.

주요 기능:

### 7.1 Error Control

데이터가 변형되거나 분실된 경우 복구한다.

### 7.2 Flow Control

송신 호스트와 수신 호스트의 처리 속도가 다른 경우 이를 조절한다.

### 수업 필기 핵심

> **논리적으로 오류 제어, 흐름 제어를 해준다.**

따라서 MAC과 LLC를 다음 질문으로 구분하면 쉽다.

``` text
MAC : How to access?
      매체에 어떻게 접근할 것인가?

LLC : Is it correct?
      데이터가 논리적으로 제대로 전달되는가?
```

------------------------------------------------------------------------

# 8. MAC vs LLC

  -----------------------------------------------------------------------
  구분                    MAC 계층(하부)          LLC 계층(상부)
  ----------------------- ----------------------- -----------------------
  관심사                  물리적 매체 접촉        데이터 논리 전달

  핵심 질문               How to access?          Is it correct?

  주요 주소               MAC 주소                SAP

  의존성                  하드웨어/케이블 종류에  상위 네트워크 계층과
                          강하게 의존             연계
  -----------------------------------------------------------------------

### 시험/기술사 관점

수업 필기에 **기술사 집중적으로 연결** 이라고 적혀 있다.

따라서 단순히 MAC/LLC의 이름을 외우기보다 다음 비교를 설명할 수 있어야
한다.

> **MAC** 은 하드웨어와 실제 전송 매체에 가까우며,\
> **LLC** 는 상위 계층과 연결되는 논리적 데이터 전달에 가깝다.

------------------------------------------------------------------------

# 9. Shared Media Access & Collision

하나의 전송 매체를 여러 노드가 함께 사용하면 문제가 발생한다.

> 두 노드가 동시에 데이터를 보내면 어떻게 되는가?

바로 **Collision(충돌)** 이다.

강의자료는 두 가지 해결 전략을 제시한다.

## 9.1 충돌 허용 후 해결

**Collision Detection / Recovery**

``` text
전송 시도
  ↓
충돌 발생
  ↓
충돌 감지
  ↓
전송 중단
  ↓
다시 전송
```

대표:

-   CSMA/CD
-   Ethernet

## 9.2 충돌을 원천적으로 방지

**Collision Avoidance / Prevention**

전송 권한을 통제하여 동시에 전송하는 상황 자체를 줄인다.

대표:

-   Token Ring
-   Time Slot
-   Token Control

### 수업 필기 핵심

사용자가 적을수록 경쟁이 적지만, **사용자가 많아지면 충돌이 많이
발생하여 효율이 떨어질 수 있다.**

이것이 자유 경쟁 방식인 Ethernet의 특성을 이해하는 중요한 포인트다.

------------------------------------------------------------------------

# 10. Shared Bus에서 데이터 전송

11페이지 그림은 공유 버스에서 데이터가 어떻게 전달되는지를 보여준다.

예를 들어 5번 노드가 1번 노드로 데이터를 전송한다고 생각하자.

``` text
1     2     3     4     5
|     |     |     |     |
=========================
                  ← DATA
```

공유 버스를 따라 데이터가 전달되면서 중간 노드들도 신호를 볼 수 있다.

### 수업 필기

-   전송
-   버스형
-   양방향
-   브로드캐스팅으로 전달
-   노드에 다 보냄
-   목적지가 다르면 `discard`
-   1번 노드가 맞으면 가져감
-   전송 완료

즉 핵심은:

> 공유 매체를 통해 신호가 전달되지만 각 노드는 목적지 정보를 보고
> 자신에게 해당하는 데이터인지 판단한다.

------------------------------------------------------------------------

# 11. Token Bus

Token Bus는 이름 때문에 헷갈리기 쉽다.

**물리적 구조는 Bus** 이지만 **논리적인 전송 순서는 Ring** 이다.

``` text
물리 구조
1 ─── 5 ─── 6 ─── 7 ─── 9
       공유 Bus

논리 구조
1 → 5 → 6 → 7 → 9 → 1
       Token 순환
```

### 강의자료

-   Physical shared bus
-   Logical ring structure
-   Token control frame으로 순차 전송

### 수업 필기 핵심

-   물리적으로는 **Bus**
-   논리적으로는 **Ring**
-   Token Bus와 Token Ring을 구분해야 함
-   앉아 있는 모양은 Bus지만 발언권은 순서대로 전달
-   CD가 없고 순서를 기다리는 방식
-   공정한 전송 방식

비유하면 회의실에 사람들이 일렬로 앉아 있어도 **발언권을 1 → 5 → 6 → 7 →
9 순서로 넘겨주는 것** 과 같다.

------------------------------------------------------------------------

# 12. Ethernet vs Token Bus

  구분        일반 Ethernet(CSMA/CD)   Token Bus(IEEE 802.4)
  ----------- ------------------------ ---------------------------
  물리 구조   공유 Bus / Star형        공유 Bus
  대화 규칙   자유 경쟁                순번제
  충돌        허용                     Token으로 통제
  장점        단순, 저렴               충돌 없음, 시간 예측 가능
  단점        부하 증가 시 성능 저하   Token 관리 복잡

핵심 비교:

``` text
Ethernet = 자유 경쟁
Token Bus = 번호표/발언권
```

사용자가 적을 때 자유 경쟁은 단순하고 효율적일 수 있지만 사용자가
많아지면 충돌 가능성이 커진다.

Token 방식은 순서를 관리해야 하므로 복잡하지만 **공정성과 예측 가능성**
을 확보할 수 있다.

------------------------------------------------------------------------

# 13. Token Ring Operational Modes

Token Ring은 순환 전송 매체에서 노드들이 Point-to-Point 방식으로
연결된다.

두 가지 동작 모드가 중요하다.

## 13.1 Listen Mode

입력 비트를 출력단으로 즉시 재전송한다.

즉 자신이 데이터를 보내는 상태가 아니라면 들어온 데이터를 다음 노드로
넘겨준다.

강의자료에서는 호스트 장애 시 자동 전환을 통해 네트워크 연속성을
유지한다고 설명한다.

### 수업 필기

> 연결성을 유지할 수 있어서 신뢰성

으로 연결하여 적어 두었다.

------------------------------------------------------------------------

## 13.2 Transmit Mode

Token을 획득하면 데이터 프레임을 전송할 권한을 가진다.

### 수업 필기 비유

> 전송 모드 = 권한 획득 전송

또한 **생각보다 훨씬 빨리 Token이 이동하므로 순간적으로 마이크를
넘겨주는 것처럼 보인다** 는 식으로 필기되어 있다.

즉:

``` text
Token 획득
   ↓
전송 권한 확보
   ↓
Frame 전송
   ↓
Token 반환/전달
   ↓
다음 노드
```

------------------------------------------------------------------------

# 14. Token Ring vs Token Bus

  구분          Token Ring                        Token Bus
  ------------- --------------------------------- -------------------------------
  물리적 형태   Ring                              Bus
  Token 전달    물리적 이웃에게 순서대로          주소 순서에 따른 논리적 순번
  장점          구조 단순, 공정한 순차 처리       Bus 설치 편의성 + Ring의 질서
  단점          한 지점 장애가 전체에 영향 가능   Token 관리 소프트웨어 복잡

### 수업 필기 핵심

Token Ring:

-   번호표에서 안정적으로 주고받음
-   공평한 매체

Token Bus:

-   나눠질 수 있고 관리가 복잡
-   A, B, C처럼 주소 순서를 정해 Token을 전달
-   순서와 시간을 두고 기다릴 수 있음
-   공정하게 채널을 사용하지만 관리가 필요

즉 둘의 공통점은 **Token을 이용한 순서 제어** 이고, 가장 큰 차이는
**물리적 연결 형태** 이다.

# 15. Collision Domain과 Broadcast Domain

## 15.1 Collision Domain

**Collision Domain** 은 네트워크에서 데이터 충돌이 발생할 수 있는
영역이다.

수업 필기:

> 여러 데이터를 동시에 전송하면 깨지는 공간

이라고 이해해 두었다.

즉 같은 Collision Domain 안에서 여러 장치가 동시에 공유 매체를 사용하면
충돌 가능성이 있다.

------------------------------------------------------------------------

## 15.2 Broadcast Domain

**Broadcast Domain** 은 Broadcast 데이터가 전달되는 범위라고 이해하면
된다.

수업 필기에는:

> 전체 다 알려도 되는 영역

이라는 식으로 정리되어 있다.

------------------------------------------------------------------------

# 16. Hub / Switch / Router와 Domain

  ------------------------------------------------------------------------
  장비         계층         Collision Domain Broadcast Domain 핵심 동작
  ------------ ------------ ---------------- ---------------- ------------
  Hub          L1                        1개              1개 입력 신호를
                                                              모든 포트로
                                                              복제

  Switch       L2                포트 수만큼              1개 MAC 주소를
                                                              보고 필요한
                                                              포트로 전달

  Router       L3                포트 수만큼      포트 수만큼 IP 주소를
                                                              보고 다른
                                                              네트워크로
                                                              전달
  ------------------------------------------------------------------------

## 16.1 Hub

Hub는 들어온 신호를 모든 포트로 그대로 복제한다.

따라서 하나의 공유 공간처럼 동작한다.

수업 필기에서도 Hub에서는 장치가 많아질수록 충돌 가능성이 커지는 점을
연결해 두었다.

------------------------------------------------------------------------

## 16.2 Switch

Switch는 **MAC 주소** 를 확인하여 필요한 포트에만 데이터를 전달한다.

따라서 각 포트가 별도의 Collision Domain이 된다.

### 수업 필기

-   MAC을 보고 필요한 곳으로 전달
-   Unicast
-   포트별로 구분

------------------------------------------------------------------------

## 16.3 Router

Router는 **IP 주소** 를 보고 서로 다른 네트워크 사이에서 경로를
찾아준다.

따라서 Broadcast Domain도 분리한다.

### 수업 필기

-   다른 Broadcast Domain을 구분
-   너무 많은 신호가 한 영역에 퍼지는 것을 분리
-   광범위한 연결과 네트워크 간 전달

### 한 번에 기억하기

``` text
Hub    → 그냥 모두에게 복제
Switch → MAC 주소 보고 전달
Router → IP 주소 보고 다른 네트워크로 전달
```

그리고:

``` text
Collision 분리: Switch부터
Broadcast 분리: Router부터
```

------------------------------------------------------------------------

# 17. CSMA/CD 상세

CSMA/CD:

> **Carrier Sense Multiple Access with Collision Detection**

슬라이드에는 `Carrier Sence`라고 표기되어 있으나 일반적인 영문 표현은
`Carrier Sense`이다. 여기서는 강의 개념을 중심으로 학습한다.

------------------------------------------------------------------------

## 17.1 Carrier Sense

데이터를 보내기 전에 케이블에 흐르는 신호, 즉 **반송파(Carrier)** 를
감지한다.

쉽게 말하면:

> "지금 누가 선로를 사용하고 있는가?"

를 먼저 확인하는 것이다.

------------------------------------------------------------------------

## 17.2 Multiple Access

여러 컴퓨터가 하나의 네트워크에 접속할 수 있도록 허용한다.

즉 하나의 공유 매체를 여러 장치가 사용한다.

------------------------------------------------------------------------

## 17.3 Collision Detection

두 컴퓨터가 거의 동시에 "선로가 비었다"고 판단하고 데이터를 보내면
충돌할 수 있다.

송신 장치는 데이터를 보내면서 동시에 충돌 발생 여부를 감지한다.

``` text
Carrier Sense
   ↓
선로가 비었는가?
   ↓ Yes
전송 시작
   ↓
Collision?
 ┌─┴─┐
No  Yes
│    ↓
│   전송 중단
│    ↓
│   일정 시간 대기
│    ↓
│   재전송
↓
완료
```

이 흐름이 **충돌을 허용하되 발생 후 감지하여 복구하는 방식** 의
핵심이다.

------------------------------------------------------------------------

# 18. 19페이지 - CSMA/CD 제목과 CSMA/CA 그림의 차이

이 페이지는 반드시 구분해서 볼 필요가 있다.

슬라이드의 제목은:

> `CSMA/CD (Carrier Sense Multiple Access with Collision Detection)`

으로 되어 있다.

본문에는:

-   Carrier Sense
-   Random Backoff
-   ACK Confirmation

이 나오며, 오른쪽 그림에는 다음 흐름이 표시되어 있다.

``` text
Source        Destination
  |               |
  |---- RTS ----->|
  |<--- CTS ------|
  |---- DATA ---->|
  |<--- ACK ------|
```

그리고 그림 아래에는 명확하게 **CSMA-CA** 라고 표시되어 있다.

따라서 이 페이지는 **제목은 CSMA/CD이지만 그림은 CSMA/CA의
RTS/CTS/DATA/ACK 흐름을 보여준다** 는 점을 그대로 기억해 두는 것이 좋다.

원자료의 표기를 임의로 하나로 합치지 말고 시험에서는 교수님의 설명
맥락을 확인해야 한다.

### 자료에 적힌 개념

**Carrier Sense**

-   데이터를 전송하기 전에 네트워크가 사용 중인지 확인

**Random Backoff**

-   네트워크가 비어 있더라도 임의의 시간 동안 기다렸다가 전송

**ACK Confirmation**

-   데이터를 보낸 뒤 목적지가 잘 받았는지 확인

# 20. Review Q2 - IPv6는 왜 128 bits인가?

강의자료 예시:

``` text
fe80:0000:0000:0000:50cd:fd4a:c05c:666a
```

IPv6 주소는 `:`로 구분된 8개의 블록으로 표현되어 있다.

각 블록은 16진수 4자리이다.

``` text
16진수 1자리 = 4 bits
4자리 = 16 bits

16 bits × 8 blocks
= 128 bits
```

따라서:

> **IPv6 주소 = 128 bits**

라고 이해할 수 있다.
