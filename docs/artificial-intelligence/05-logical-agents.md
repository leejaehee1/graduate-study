## 1. 지식 기반 에이전트 (Knowledge-based Agents)

### 1.1 구조: 지식 베이스 + 추론 엔진

```
┌──────────────────────────────────────────────┐
│  Inference engine (추론 엔진)                  │ ← 도메인 독립적인 알고리즘
│  어떤 분야에서든 똑같이 쓰는 추론 방법             │
├──────────────────────────────────────────────┤
│  Knowledge base (지식 베이스, KB)               │ ← 도메인 특화 내용
│  이 분야(웜푸스 세계)에 대한 사실과 규칙           │
└──────────────────────────────────────────────┘
```

| 구성 요소 | 성격 | 예 |
|---|---|---|
| **지식 베이스 (KB)** | **도메인 특화**(domain-specific) 내용 | "구덩이 옆 칸에는 바람이 분다", "[1,1]에는 바람이 없었다" |
| **추론 엔진** | **도메인 독립**(domain-independent) 알고리즘 | 진리표 검사, 도출(resolution) 등 |

> **지식 베이스 = 형식 언어(formal language)로 쓴 문장(sentence)들의 집합**

- 여기서 **문장** 은 일상 문장이 아니라 **정해진 문법을 따르는 기호 표현** 이다 (예: `B₁,₁ ⇔ (P₁,₂ ∨ P₂,₁)`).
- 장점: 추론 엔진은 그대로 두고 **KB만 바꾸면** 다른 분야에도 쓸 수 있다.

### 1.2 선언적 접근 (Declarative Approach)

에이전트(또는 시스템)를 만드는 **선언적** 방법:

1. **Tell(알려 주기)**: 에이전트가 알아야 할 것을 KB에 **말해 준다**.
2. **Ask(묻기)**: 그다음 에이전트가 **스스로에게** 무엇을 할지 **묻는다** → 답은 **KB로부터 따라 나와야** 한다.

| 접근 | 방식 | 비유 |
|---|---|---|
| **선언적** (declarative) | "**무엇이** 참인지"를 알려 주고, 행동은 추론으로 결정 | 지도와 교통 규칙을 알려 주고 알아서 길을 찾게 함 |
| 절차적 (procedural) **[보충]** | "**어떻게** 행동할지"를 코드로 직접 작성 | "첫 번째 사거리에서 좌회전, 그다음 직진…" 을 프로그래밍 |

### 1.3 에이전트를 바라보는 두 수준

| 수준 | 관점 | 질문 |
|---|---|---|
| **지식 수준** (knowledge level) | 에이전트가 **무엇을 아는가** (어떻게 구현했는지와 무관) | "택시는 금문교가 샌프란시스코와 마린 카운티를 잇는다는 것을 안다" |
| **구현 수준** (implementation level) | KB의 **자료구조** 와 그것을 다루는 **알고리즘** | "그 사실이 연결 리스트에 저장되어 있는가, 해시 테이블에 있는가?" |

> 💡 지식 수준에서 에이전트를 설명할 수 있으면, 구현 세부 사항을 몰라도 **행동을 예측** 할 수 있다.

### 1.4 간단한 지식 기반 에이전트

```
function KB-AGENT(percept) returns an action
    static: KB, a knowledge base
            t, a counter, initially 0, indicating time

    TELL(KB, MAKE-PERCEPT-SENTENCE(percept, t))
    action ← ASK(KB, MAKE-ACTION-QUERY(t))
    TELL(KB, MAKE-ACTION-SENTENCE(action, t))
    t ← t + 1
    return action
```

**한 줄씩 해석**

| 줄 | 하는 일 | 웜푸스 예 |
|---|---|---|
| `TELL(KB, 인지 문장)` | 지금 받은 인지를 **문장으로 바꿔** KB에 추가 | "시각 3에 [2,1]에서 바람을 느꼈다" |
| `action ← ASK(KB, 행동 질의)` | KB에 "지금 **무엇을 해야** 하는가?"를 묻고 **추론** 으로 답을 얻음 | "[1,2]로 가는 것이 안전한가?" → 이동 |
| `TELL(KB, 행동 문장)` | 선택한 행동을 했다는 사실도 KB에 **기록** | "시각 3에 Forward를 했다" |
| `t ← t + 1` | 시간 증가 | |

- `MAKE-PERCEPT-SENTENCE`, `MAKE-ACTION-QUERY`, `MAKE-ACTION-SENTENCE` 는 인지·질의·행동을 **KB의 언어로 번역** 하는 함수
- 2장의 **상태를 가진 반사 에이전트** 와 비교하면, 내부 상태가 "문장들의 집합(KB)"이 된 것이다.

**에이전트가 갖춰야 할 능력**

1. 상태, 행동 등을 **표현** 할 수 있어야 한다.
2. 새로운 **인지를 반영** 할 수 있어야 한다.
3. 세계에 대한 **내부 표현을 갱신** 할 수 있어야 한다.
4. 세계의 **숨겨진 속성을 추론** 할 수 있어야 한다. (예: 보이지 않는 구덩이의 위치)
5. 적절한 **행동을 추론** 할 수 있어야 한다.

→ 이 능력들이 왜 필요한지 보여 주는 예가 바로 **웜푸스 세계** 다.

## 2. 웜푸스 세계 (Wumpus World)

### 2.1 이야기

> 동굴 어딘가에 무시무시한 **웜푸스(wumpus)** 가 숨어 있다. 웜푸스는 자기 방에 들어온 자를 잡아먹는다. 에이전트는 웜푸스를 쏠 수 있지만 **화살은 단 한 발** 뿐이다. 어떤 방에는 **바닥 없는 구덩이(pit)** 가 있어서 들어가면 빠진다 (웜푸스는 너무 커서 빠지지 않는다). 이 암울한 환경의 유일한 희망은 **금 더미** 를 찾을 수 있다는 것이다.

### 2.2 지도 (예시)

```
     1         2         3         4
  ┌─────────┬─────────┬─────────┬─────────┐
4 │ Stench  │         │ Breeze  │  PIT    │
  │         │         │         │         │
  ├─────────┼─────────┼─────────┼─────────┤
3 │ WUMPUS  │ Breeze  │  PIT    │ Breeze  │
  │         │ Stench  │         │         │
  │         │ Gold    │         │         │
  ├─────────┼─────────┼─────────┼─────────┤
2 │ Stench  │         │ Breeze  │         │
  │         │         │         │         │
  ├─────────┼─────────┼─────────┼─────────┤
1 │  START  │ Breeze  │  PIT    │ Breeze  │
  │  (에이전트)│         │         │         │
  └─────────┴─────────┴─────────┴─────────┘
       ↑ [열, 행] 좌표: 시작 칸은 [1,1]
```

- 웜푸스는 [1,3], 금은 [2,3], 구덩이는 [3,1], [3,3], [4,4]
- 웜푸스 주변(상하좌우)에는 **Stench(악취)**, 구덩이 주변에는 **Breeze(바람)** 가 있다.
- ⚠️ 이 지도는 **전지적 시점** 이다. 에이전트는 이것을 **모른 채** [1,1]에서 출발한다.

### 2.3 PEAS 기술 (2장 복습)

| PEAS | 내용 |
|---|---|
| **P (성능 척도)** | 금을 들고 나오면 **+1000**, 죽으면 **−1000**, 한 걸음마다 **−1**, 화살 사용 **−10**. 에이전트가 죽거나 동굴 밖으로 나오면(Climb) 게임 종료 |
| **E (환경)** | **4×4 격자** 의 방. 에이전트는 항상 **[1,1]에서 오른쪽을 보고** 시작. 금과 웜푸스의 위치는 시작 칸을 제외한 칸 중 **균등 분포로 무작위** 선택. 시작 칸 외의 각 칸은 **확률 0.2** 로 구덩이 |
| **A (액추에이터)** | Left turn(왼쪽으로 돌기), Right turn(오른쪽으로 돌기), Forward(전진), Grab(줍기), Release(내려놓기), Shoot(쏘기), Climb(올라가기) |
| **S (센서)** | **5개**, 각각 **1비트** 정보 (아래 표) |

**5가지 센서**

| 센서 | 언제 감지되나 |
|---|---|
| **Stench** (악취) | 웜푸스가 있는 칸과 **바로 인접한**(대각선 제외) 칸 |
| **Breeze** (바람) | 구덩이와 **바로 인접한** 칸 |
| **Glitter** (반짝임) | **금이 있는 칸** |
| **Bump** (부딪힘) | 벽으로 걸어 들어갔을 때 |
| **Scream** (비명) | 웜푸스가 죽었을 때. **동굴 어디서나** 들림 |

- 인지는 5개 값의 리스트로 주어진다. 예: `[Stench, Breeze, None, None, None]` = 악취와 바람은 있고 반짝임·부딪힘·비명은 없음

### 2.4 환경 특성 (2장의 분류 기준 적용)

| 특성 | 답 | 이유 |
|---|---|---|
| **관측 가능?** | **아니오** (부분 관측) | **국지적 인지만** 가능. 구덩이·웜푸스 위치를 직접 볼 수 없음 |
| **결정적?** | **예** | 행동의 결과가 정확히 정해져 있음 |
| **에피소드형?** | **아니오** | 행동 단위에서 **순차적** |
| **정적?** | **예** | 웜푸스와 구덩이는 **움직이지 않음** |
| **이산?** | **예** | |
| **단일 에이전트?** | **예** | 웜푸스는 사실상 **자연물(지형)** 처럼 취급 (움직이거나 전략적으로 행동하지 않음) |

> 💡 핵심은 **부분 관측** 이다. 볼 수 없는 것을 **추론** 해야 하므로 논리가 필요하다.

### 2.5 웜푸스 세계 탐험하기 (추론의 흐름)

슬라이드의 탐험 장면을 단계별로 정리하면 다음과 같다. (표기: **A** = 에이전트, **OK** = 안전, **B** = 바람, **S** = 악취, **P?** = 구덩이일 수도, **W?** = 웜푸스일 수도, **V** = 방문함)

**① [1,1] 출발: 아무것도 감지 안 됨** `[None, None, None, None, None]`

```
   ┌────┬────┬────┬────┐
 2 │ OK │    │    │    │
   ├────┼────┼────┼────┤
 1 │ A  │ OK │    │    │
   │ OK │    │    │    │
   └────┴────┴────┴────┘
     1    2    3    4
```
- 바람도 악취도 없음 → 인접한 [1,2], [2,1]에는 **구덩이도 웜푸스도 없다** → 둘 다 **OK**

**② [2,1]로 이동: Breeze 감지** `[None, Breeze, None, None, None]`

```
   ┌────┬────┬────┬────┐
 2 │ OK │ P? │    │    │
   ├────┼────┼────┼────┤
 1 │ V  │ A  │ P? │    │
   │ OK │ B  │    │    │
   └────┴────┴────┴────┘
```
- 바람이 분다 → 인접 칸 [2,2] 또는 [3,1] 중 **적어도 하나에 구덩이** → 둘 다 **P?**
- 위험하므로 되돌아가 아직 안전한 [1,2]로 간다.

**③ [1,2]로 이동: Stench 감지** `[Stench, None, None, None, None]`

```
   ┌────┬────┬────┬────┐
 3 │ W! │    │    │    │
   ├────┼────┼────┼────┤
 2 │ A  │ OK │    │    │
   │ S  │    │    │    │
   ├────┼────┼────┼────┤
 1 │ V  │ V  │ P! │    │
   │ OK │ B  │    │    │
   └────┴────┴────┴────┘
```
- **악취** → 웜푸스는 [1,3] 또는 [2,2]. 그런데 [2,1]에서는 악취가 없었으므로 [2,2]에는 웜푸스가 **없다** → 웜푸스는 **[1,3]** (W!)
- **바람 없음** → [2,2]에는 구덩이가 **없다**. 그러면 ②의 "[2,2] 또는 [3,1]에 구덩이"에서 → 구덩이는 **[3,1]** (P!)
- 따라서 [2,2]는 **OK**

> 💡 이것이 **추론** 이다. 서로 다른 시점·장소에서 얻은 정보를 **결합** 해서, 직접 보지 못한 [1,3]의 웜푸스와 [3,1]의 구덩이를 **확정** 했다.

**④ [2,2] → [2,3]: Glitter!** → 금을 줍고(Grab) 돌아가 [1,1]에서 Climb

### 2.6 곤란한 상황들 (Other Tight Spots)

**상황 1: [1,2]와 [2,1] 모두에서 바람**

```
   ┌────┬────┬────┐
 3 │ P? │    │    │
   ├────┼────┼────┤
 2 │ B  │ P? │    │
   │ OK │    │    │
   ├────┼────┼────┤
 1 │ A  │ B  │ P? │
   │ OK │ OK │    │
   └────┴────┴────┘
```
- 인접한 미방문 칸 [1,3], [2,2], [3,1]이 모두 **P?** → **안전한 행동이 없다**
- 슬라이드의 질문: 구덩이가 균등하게(각 칸 확률 0.2로) 분포한다면 **[2,2]에 구덩이가 있을 확률은?**
- **[보충] 답: 약 0.86** (13장 확률 추론에서 다룸)
  - [2,2]에 구덩이가 있으면 **두 바람을 한 번에** 설명할 수 있다.
  - [2,2]에 없으면 [1,3]과 [3,1]에 **둘 다** 구덩이가 있어야 해서 가능성이 훨씬 낮다.
  - 계산해 보면 P([2,2]에 구덩이) ≈ **0.86**, P([1,3]에 구덩이) = P([3,1]에 구덩이) ≈ **0.31**
  - → 논리만으로는 "모른다"지만 **확률로는 [1,3]이나 [3,1]로 가는 편이 낫다**. 논리의 한계를 보여 주는 예

**상황 2: 시작 칸 [1,1]에서 바로 악취**

- 웜푸스가 [1,2] 또는 [2,1]에 있다 → **움직일 수 없다**
- **강요(coercion) 전략**: 정면(오른쪽, [2,1] 방향)으로 **화살을 쏜다**
  - 웜푸스가 거기 있었다면 → **죽음**(비명 들림) → [2,1]은 **안전**
  - 웜푸스가 거기 없었다면 → [2,1]은 **안전** (웜푸스는 [1,2]에 있음)
  - → **어느 경우든** [2,1]이 안전해진다!

## 3. 논리 일반: 구문, 의미, 함의, 모델

### 3.1 논리란?

> **논리(logic)**: 정보를 표현하는 **형식 언어** 로, 그 표현으로부터 **결론을 이끌어낼 수 있는** 것

| 구성 요소 | 정의 | 산술 예 |
|---|---|---|
| **구문 (syntax)** | 언어에서 **올바른 문장** 이 무엇인지 정의 (문법) | `x + 2 ≥ y` 는 문장 ✅ / `x2 + y >` 는 문장이 아님 ❌ |
| **의미 (semantics)** | 문장의 **"뜻"**, 즉 어떤 **세계에서 문장이 참인지** 정의 | `x + 2 ≥ y` 는 수 x+2가 수 y보다 작지 않을 때, 그리고 그때만(iff) 참 |

**같은 문장이라도 세계에 따라 참·거짓이 달라진다**

| 세계 | `x + 2 ≥ y` |
|---|---|
| x = 7, y = 1 | 9 ≥ 1 → **참** |
| x = 0, y = 6 | 2 ≥ 6 → **거짓** |

> 💡 **iff** = "if and only if", **필요충분조건**(~일 때, 그리고 그때만). 논리 정의에 자주 나온다.

### 3.2 함의 (Entailment) ⭐⭐

> **함의**: 하나가 다른 것으로부터 **따라 나온다** (follows from)
>
> **KB ⊨ α** (KB가 α를 함의한다)
> ⇔ **KB가 참인 모든 세계에서 α도 참** 이다

- 기호 **⊨** 는 "함의한다(entails)"로 읽는다.

**예시**

| KB | α | KB ⊨ α? | 이유 |
|---|---|---|---|
| "자이언츠가 이겼다" 그리고 "레즈가 이겼다" | "자이언츠가 이겼거나 레즈가 이겼다" | **예** | 둘 다 이긴 세계에서는 "둘 중 하나가 이겼다"도 당연히 참 |
| x + y = 4 | 4 = x + y | **예** | 같은 내용을 다르게 쓴 것 |
| "자이언츠가 이겼거나 레즈가 이겼다" | "자이언츠가 이겼다" | **아니오** | 레즈만 이긴 세계에서는 KB는 참인데 α는 거짓 |

> ⭐ 함의는 **문장들 사이의 관계**(즉 **구문** 의 문제)이지만, 그 판단은 **의미**(어떤 세계에서 참인가)에 **기반** 한다.

### 3.3 모델 (Models)

> **모델(model)**: 문장의 참·거짓을 평가할 수 있도록 **형식적으로 구조화된 세계**. 쉽게 말해 "가능한 세계 하나"

| 표기 | 의미 |
|---|---|
| **m은 α의 모델이다** | 세계 m에서 문장 α가 **참** |
| **M(α)** | α의 **모든 모델의 집합** (α가 참인 세계들 전부) |

이 정의로 함의를 **집합의 포함 관계** 로 다시 쓸 수 있다.

> ⭐ **KB ⊨ α ⇔ M(KB) ⊆ M(α)**
> "KB가 참인 세계들"이 "α가 참인 세계들" **안에 모두 들어 있다**

```
┌──────────────── 가능한 모든 세계 ────────────────┐
│                                                   │
│        ┌──────── M(α) ────────┐                   │
│        │  α = "자이언츠가 이겼다"│                   │
│        │                       │                   │
│        │   ┌── M(KB) ──┐       │                   │
│        │   │ 자이언츠 승  │       │                   │
│        │   │ 그리고 레즈 승│       │                   │
│        │   └───────────┘       │                   │
│        └───────────────────────┘                   │
└───────────────────────────────────────────────────┘
     M(KB) ⊆ M(α) 이므로 KB ⊨ α
```

> 💡 **직관**: KB가 **더 많은 것을 주장할수록** 그것이 참인 세계는 **더 적어진다**(M(KB)가 작아짐). 작은 집합일수록 다른 집합 안에 쏙 들어가기 쉬우므로 **더 많은 것을 함의** 한다.

## 4. 웜푸스 세계에서의 함의: 모델 검사

### 4.1 상황 설정

> [1,1]에서 **아무것도 감지하지 못하고**, 오른쪽으로 이동해 **[2,1]에서 바람** 을 감지한 상황

```
   ┌────┬────┬────┐
 2 │ ?  │ ?  │    │
   ├────┼────┼────┤
 1 │ A  │ A  │ ?  │
   │    │ B  │    │
   └────┴────┴────┘
     1    2    3
```

- 구덩이만 고려하면, 모르는 칸은 **[1,2], [2,2], [3,1]** 세 개
- 각 칸이 구덩이인지 아닌지 **참/거짓 2가지** → 2 × 2 × 2 = **8가지 가능한 모델**

### 4.2 8가지 모델과 KB

**KB = 웜푸스 세계의 규칙 + 관측 내용**

| 모델 | [1,2] | [2,2] | [3,1] | [1,1]에 바람 없음과 일치? | [2,1]에 바람과 일치? | **KB 참?** |
|---|---|---|---|---|---|---|
| 1 | – | – | – | ✅ | ❌ (구덩이가 없는데 바람) | ❌ |
| 2 | – | – | 구덩이 | ✅ | ✅ | **✅** |
| 3 | – | 구덩이 | – | ✅ | ✅ | **✅** |
| 4 | – | 구덩이 | 구덩이 | ✅ | ✅ | **✅** |
| 5 | 구덩이 | – | – | ❌ ([1,1]에 바람이 있어야 함) | ❌ | ❌ |
| 6 | 구덩이 | – | 구덩이 | ❌ | ✅ | ❌ |
| 7 | 구덩이 | 구덩이 | – | ❌ | ✅ | ❌ |
| 8 | 구덩이 | 구덩이 | 구덩이 | ❌ | ✅ | ❌ |

→ **KB가 참인 모델은 2, 3, 4 세 개뿐** 이다 (M(KB) = {2, 3, 4})

### 4.3 질문 1: α₁ = "[1,2]는 안전하다"

- α₁이 참인 모델 = [1,2]에 구덩이가 없는 모델 = {1, 2, 3, 4}
- M(KB) = {2, 3, 4} ⊆ M(α₁) = {1, 2, 3, 4} ✅
- 따라서 **KB ⊨ α₁** — [1,2]는 **안전하다고 증명** 된다.

> 이렇게 **가능한 모델을 모두 나열해서** 함의를 확인하는 방법을 **모델 검사(model checking)** 라고 한다.

### 4.4 질문 2: α₂ = "[2,2]는 안전하다"

- α₂가 참인 모델 = [2,2]에 구덩이가 없는 모델 = {1, 2, 5, 6}
- M(KB) = {2, 3, 4} ⊄ M(α₂) — 모델 3, 4는 KB는 참인데 α₂는 거짓
- 따라서 **KB ⊭ α₂** — [2,2]가 안전하다고 **결론 내릴 수 없다**

```
         M(α₁) = {1,2,3,4}                 M(α₂) = {1,2,5,6}
       ┌─────────────────┐               ┌─────────────────┐
       │ 1 ┌──────────┐  │               │ 1         5     │
       │   │ 2  3  4  │  │          ┌────┼──┐              │
       │   │  M(KB)   │  │          │ 3  │ 2│   6          │
       │   └──────────┘  │          │ 4  └──┼──────────────┘
       └─────────────────┘          └───────┘ M(KB)가 삐져나옴
          KB ⊨ α₁ ✅                        KB ⊭ α₂ ❌
```

> ⚠️ "KB ⊭ α₂"는 "[2,2]가 위험하다"는 뜻이 **아니다**. "안전하다고 **증명할 수 없다**"는 뜻이다. (모델 2에서는 실제로 안전하다)

## 5. 추론 (Inference): 건전성과 완전성

### 5.1 추론의 정의

> **KB ⊢ᵢ α**: 문장 α를 KB로부터 **절차 i로 도출할 수 있다**

- 기호 **⊢** 는 "도출한다(derives)"로 읽는다. 아래 첨자 i는 **어떤 추론 절차** 인지를 나타낸다.

**바늘과 건초더미 비유**

| 개념 | 비유 |
|---|---|
| KB의 모든 귀결(결과)들 | **건초더미** |
| α | **바늘** |
| **함의 (⊨)** | 바늘이 건초더미 **안에 있다** 는 사실 |
| **추론 (⊢)** | 바늘을 **찾아내는** 과정 |

| | 함의 ⊨ | 추론 ⊢ |
|---|---|---|
| 성격 | **의미적** 관계 (참·거짓, 모델) | **구문적** 절차 (기호 조작, 알고리즘) |
| 질문 | "α가 **정말로** 따라 나오는가?" | "알고리즘이 α를 **찾아내는가**?" |

### 5.2 건전성과 완전성 ⭐⭐

| 성질 | 정의 | 의미 | 위반하면 |
|---|---|---|---|
| **건전성 (soundness)** | KB ⊢ᵢ α 이면 언제나 KB ⊨ α | 절차 i는 **함의된 문장만** 도출한다 | **거짓을 지어냄** (없는 바늘을 찾았다고 함) |
| **완전성 (completeness)** | KB ⊨ α 이면 언제나 KB ⊢ᵢ α | 함의된 문장은 **모두** 도출할 수 있다 | **놓치는 것이 있음** (있는 바늘을 못 찾음) |

```
              건전성: ⊢ 이면 ⊨       (도출한 것은 모두 진짜)
   KB ⊢ᵢ α  ═══════════════════▶  KB ⊨ α
            ◀═══════════════════
              완전성: ⊨ 이면 ⊢       (진짜는 모두 도출 가능)
```

> 💡 **3장과 비교**: 탐색 알고리즘의 **완전성**("해가 있으면 반드시 찾는다")과 같은 개념이다. 이상적인 추론 절차는 **건전하고 완전** 하다.

## 6. 명제 논리: 구문 (Syntax)

**명제 논리(propositional logic)** 는 **가장 단순한 논리** 로, 논리의 기본 아이디어를 보여 주기에 좋다. (Boolean logic, 불 논리라고도 함)

### 6.1 문장을 만드는 규칙

| 규칙 | 형태 | 이름 | 읽는 법 |
|---|---|---|---|
| 명제 기호 P₁, P₂ 등은 문장이다 | P₁ | **원자 문장** | |
| S가 문장이면 ¬S도 문장 | ¬S | **부정** (negation) | not S |
| S₁, S₂가 문장이면 S₁ ∧ S₂도 문장 | S₁ ∧ S₂ | **연언** (conjunction) | S₁ and S₂ |
| S₁, S₂가 문장이면 S₁ ∨ S₂도 문장 | S₁ ∨ S₂ | **선언** (disjunction) | S₁ or S₂ |
| S₁, S₂가 문장이면 S₁ ⇒ S₂도 문장 | S₁ ⇒ S₂ | **함축** (implication) | S₁ implies S₂ / if S₁ then S₂ |
| S₁, S₂가 문장이면 S₁ ⇔ S₂도 문장 | S₁ ⇔ S₂ | **쌍조건** (biconditional) | S₁ if and only if S₂ |

### 6.2 BNF 문법 (교재 Fig. 7.7)

```
Sentence         → AtomicSentence | ComplexSentence
AtomicSentence   → True | False | P | Q | R | ...
ComplexSentence  → ( Sentence )
                 | ¬ Sentence
                 | Sentence ∧ Sentence
                 | Sentence ∨ Sentence
                 | Sentence ⇒ Sentence
                 | Sentence ⇔ Sentence

OPERATOR PRECEDENCE : ¬, ∧, ∨, ⇒, ⇔      (높음 → 낮음)
```

- **BNF (Backus–Naur Form)**: 문법을 정의하는 표기법. `→` 는 "~로 이루어진다", `|` 는 "또는"
- **연산자 우선순위**: **¬ > ∧ > ∨ > ⇒ > ⇔** (산술의 곱셈이 덧셈보다 먼저인 것과 같음)

**우선순위 적용 예**

| 문장 | 괄호로 명확히 쓰면 |
|---|---|
| ¬A ∧ B | (¬A) ∧ B |
| A ∧ B ∨ C | (A ∧ B) ∨ C |
| A ∨ B ⇒ C | (A ∨ B) ⇒ C |
| ¬P ∨ Q ∧ R ⇒ S | ((¬P) ∨ (Q ∧ R)) ⇒ S |

## 7. 명제 논리: 의미 (Semantics)와 진리표

### 7.1 모델 = 각 명제 기호에 참/거짓 배정

예: 명제 기호가 P₁,₂, P₂,₂, P₃,₁ 세 개일 때 하나의 모델

| P₁,₂ | P₂,₂ | P₃,₁ |
|---|---|---|
| true | true | false |

- 기호가 3개면 가능한 모델은 2³ = **8개** → 자동으로 **나열(enumerate)** 할 수 있다.
- 기호가 n개면 모델은 **2ⁿ개**

### 7.2 모델 m에서 참을 평가하는 규칙

| 문장 | 참이 되는 조건 |
|---|---|
| ¬S | S가 **거짓** 일 때, 그리고 그때만 |
| S₁ ∧ S₂ | S₁이 참 **그리고** S₂가 참 |
| S₁ ∨ S₂ | S₁이 참 **또는** S₂가 참 |
| S₁ ⇒ S₂ | S₁이 **거짓** 또는 S₂가 참 = S₁이 참이고 S₂가 거짓일 때**만 거짓** |
| S₁ ⇔ S₂ | S₁ ⇒ S₂ 가 참 **그리고** S₂ ⇒ S₁ 이 참 (= 두 값이 **같을 때**) |

**재귀적 평가 예** (위 모델: P₁,₂ = true, P₂,₂ = true, P₃,₁ = false)

```
¬P₁,₂ ∧ (P₂,₂ ∨ P₃,₁)
```

⚠️ 슬라이드는 `true ∧ (false ∨ true) = true` 로 계산하는데, 이것은 위 모델이 아니라 **P₁,₂ = false, P₂,₂ = false, P₃,₁ = true** 인 모델에서의 계산이다. 위 표의 모델(true, true, false)로 계산하면 다음과 같다.

```
¬P₁,₂ ∧ (P₂,₂ ∨ P₃,₁)
= ¬true ∧ (true ∨ false)
= false ∧ true
= false
```

> 💡 어느 모델이든 **안쪽부터 바깥으로**, 위 규칙을 **재귀적으로** 적용하면 어떤 문장이든 평가할 수 있다.

### 7.3 진리표 (Truth Tables for Connectives) ⭐

| P | Q | ¬P | P ∧ Q | P ∨ Q | P ⇒ Q | P ⇔ Q |
|---|---|---|---|---|---|---|
| false | false | true | false | false | **true** | true |
| false | true | true | false | true | **true** | false |
| true | false | false | false | true | **false** | false |
| true | true | false | true | true | true | true |

**⚠️ 함축 (⇒) 이 헷갈리는 이유**

- P가 **거짓** 이면 P ⇒ Q 는 Q와 상관없이 **항상 참** 이다.
- 비유: "**비가 오면** 우산을 가져간다"는 약속
  - 비가 오고 우산을 가져감 → 약속 지킴 (참)
  - 비가 오는데 우산 안 가져감 → **약속 어김 (거짓)** ← 유일하게 거짓
  - 비가 안 왔음 → 우산을 가져가든 말든 약속을 **어긴 것은 아님** (참)
- 또 명제 논리의 ⇒ 는 **인과 관계를 요구하지 않는다**. "5는 홀수 ⇒ 도쿄는 일본의 수도" 도 참이다.

## 8. 웜푸스 세계를 명제 논리로

### 8.1 명제 기호 정의

- **Pᵢ,ⱼ**: [i, j]에 **구덩이(pit)** 가 있으면 참
- **Bᵢ,ⱼ**: [i, j]에 **바람(breeze)** 이 불면 참

### 8.2 지식 베이스

**관측 사실**

| 이름 | 문장 | 의미 |
|---|---|---|
| R₁ | ¬P₁,₁ | [1,1]에는 구덩이가 없다 (시작 칸) |
| R₂ | ¬B₁,₁ | [1,1]에는 바람이 없다 (관측) |
| R₃ | B₂,₁ | [2,1]에는 바람이 분다 (관측) |

**규칙: "구덩이는 인접 칸에 바람을 일으킨다"**

슬라이드는 이것을 더 정확하게 "**칸에 바람이 분다 ⇔ 인접 칸에 구덩이가 있다**"로 표현한다.

| 이름 | 문장 | 의미 |
|---|---|---|
| R₄ | B₁,₁ ⇔ (P₁,₂ ∨ P₂,₁) | [1,1]에 바람이 분다 ⇔ [1,2]나 [2,1]에 구덩이가 있다 |
| R₅ | B₂,₁ ⇔ (P₁,₁ ∨ P₂,₂ ∨ P₃,₁) | [2,1]에 바람이 분다 ⇔ [1,1], [2,2], [3,1] 중 어딘가에 구덩이가 있다 |

> **KB = R₁ ∧ R₂ ∧ R₃ ∧ R₄ ∧ R₅**

> 💡 **왜 ⇒ 가 아니라 ⇔ 인가?**
> - "구덩이 ⇒ 바람"만 쓰면 "바람이 없으면 구덩이도 없다"를 이끌어낼 수 있지만,
> - "바람이 분다 ⇒ 근처에 구덩이가 있다"는 **⇔ 의 반대 방향** 이 있어야 나온다.
> - 2.5절의 ②에서 "[2,1]에 바람 → [2,2]나 [3,1]에 구덩이"를 추론한 것이 바로 이 방향이다.

## 9. 진리표 추론과 TT-Entails

### 9.1 진리표로 추론하기

기호는 B₁,₁, B₂,₁, P₁,₁, P₁,₂, P₂,₁, P₂,₂, P₃,₁ **7개** → 모델은 2⁷ = **128개**

**방법**: 모든 행(모델)을 나열한다. **KB가 참인 행이 있으면, 그 행에서 α도 참인지 확인** 한다.

| B₁,₁ | B₂,₁ | P₁,₁ | P₁,₂ | P₂,₁ | P₂,₂ | P₃,₁ | R₁ | R₂ | R₃ | R₄ | R₅ | **KB** |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| F | F | F | F | F | F | F | T | T | F | T | T | F |
| F | F | F | F | F | F | T | T | T | F | T | F | F |
| ⋮ | | | | | | | | | | | | |
| F | T | F | F | F | F | F | T | T | T | T | F | F |
| F | T | F | F | F | F | **T** | T | T | T | T | T | **T** |
| F | T | F | F | F | **T** | F | T | T | T | T | T | **T** |
| F | T | F | F | F | **T** | **T** | T | T | T | T | T | **T** |
| F | T | F | F | T | F | F | T | T | T | F | F | F |
| ⋮ | | | | | | | | | | | | |
| T | T | T | T | T | T | T | F | F | T | T | T | F |

(R 열은 8.2절의 번호를 따름: R₁ = ¬P₁,₁, R₂ = ¬B₁,₁, R₃ = B₂,₁, R₄·R₅ = 규칙)

- **KB가 참인 행은 128개 중 단 3개** 이고, 세 행 모두 **P₁,₂ = false** → **KB ⊨ ¬P₁,₂** ([1,2]는 안전)
- 4장의 그림 설명(8개 모델 중 3개)과 **같은 결론** 이다. B와 나머지 P 기호까지 포함해 표를 키웠을 뿐이다.

> ⚠️ **슬라이드 표기 주의**
> - 이 슬라이드(p.35) 아래쪽에서는 R₂와 R₄의 번호가 8.2절과 **바뀌어** 있다 (R₂: B₁,₁ ⇔ …, R₄: ¬B₁,₁). 내용은 같다.
> - 슬라이드의 `α = P₁,₂` 는 **¬P₁,₂** ("[1,2]에 구덩이가 없다", 즉 안전)로 읽어야 한다. KB가 참인 세 행에서 P₁,₂는 모두 거짓이므로, 함의되는 것은 ¬P₁,₂다.

### 9.2 TT-Entails 알고리즘 (열거에 의한 추론)

> **모든 모델을 깊이 우선으로 열거** 하는 방법은 **건전하고 완전** 하다.

```
function TT-ENTAILS?(KB, α) returns true or false
    inputs: KB, the knowledge base, a sentence in propositional logic
            α, the query, a sentence in propositional logic

    symbols ← a list of the proposition symbols in KB and α
    return TT-CHECK-ALL(KB, α, symbols, [ ])

function TT-CHECK-ALL(KB, α, symbols, model) returns true or false
    if EMPTY?(symbols) then
        if PL-TRUE?(KB, model) then return PL-TRUE?(α, model)
        else return true
    else do
        P ← FIRST(symbols); rest ← REST(symbols)
        return TT-CHECK-ALL(KB, α, rest, EXTEND(P, true, model)) and
               TT-CHECK-ALL(KB, α, rest, EXTEND(P, false, model))
```

**한 줄씩 해석**

| 부분 | 의미 |
|---|---|
| `symbols` | KB와 α에 나오는 모든 명제 기호 |
| `EMPTY?(symbols)` | 모든 기호에 값을 다 배정했다 = **완성된 모델 하나** |
| `PL-TRUE?(KB, model)` 이면 `PL-TRUE?(α, model)` 반환 | KB가 참인 모델이면 **α도 참이어야** 한다 |
| KB가 거짓이면 `return true` | KB가 거짓인 세계는 **검사할 필요가 없다** (함의의 정의상 상관없음) |
| `EXTEND(P, true/false, model)` | 기호 P를 **참으로 한 번, 거짓으로 한 번** 배정해 재귀 → 이진 트리를 깊이 우선 탐색 |
| `and` | **모든** 가지에서 참이어야 참 → 하나라도 반례(KB 참, α 거짓)가 있으면 false |

```
                    (빈 모델)
               B₁,₁=T /      \ B₁,₁=F
                 ...          ...
                 /  \        /    \
               ...  ...    ...    ...       ← 깊이 = 기호 수 n
              (잎 = 완성된 모델, 2ⁿ개)
```

**성질**

| 기준 | 결과 |
|---|---|
| 건전성 | ✅ 진리표를 그대로 확인하므로 |
| 완전성 | ✅ 모델 수가 유한하므로 모두 확인 가능 |
| 시간 복잡도 | **O(2ⁿ)** — 기호가 n개면 모델 2ⁿ개 → 기호가 많으면 **비현실적** |
| 공간 복잡도 | **O(n)** — 깊이 우선이라 현재 경로만 저장 (3장의 DFS와 같은 이유) |

> 💡 **3장과 연결**: TT-CHECK-ALL은 "모델 공간"을 **깊이 우선 탐색** 하는 것이다. 그래서 공간은 선형이지만 시간은 지수적이다.

### 9.3 [보충] Python으로 직접 돌려 보기

위 의사코드를 그대로 옮긴 코드다. 직접 실행해서 결과를 확인했다.

```python
from itertools import product

SYMBOLS = ["B11", "B21", "P11", "P12", "P21", "P22", "P31"]

def iff(a, b):
    return a == b

def KB(m):
    R1 = not m["P11"]
    R2 = not m["B11"]
    R3 = m["B21"]
    R4 = iff(m["B11"], m["P12"] or m["P21"])
    R5 = iff(m["B21"], m["P11"] or m["P22"] or m["P31"])
    return R1 and R2 and R3 and R4 and R5

def tt_entails(kb, alpha, symbols):
    def check_all(symbols, model):
        if not symbols:                                  # 모델 완성
            return alpha(model) if kb(model) else True
        p, rest = symbols[0], symbols[1:]
        return (check_all(rest, {**model, p: True}) and  # P = 참
                check_all(rest, {**model, p: False}))    # P = 거짓
    return check_all(symbols, {})

alpha1 = lambda m: not m["P12"]   # [1,2]는 안전하다
alpha2 = lambda m: not m["P22"]   # [2,2]는 안전하다

print(tt_entails(KB, alpha1, SYMBOLS))   # True
print(tt_entails(KB, alpha2, SYMBOLS))   # False

# KB가 참인 모델 확인
for values in product([False, True], repeat=len(SYMBOLS)):
    m = dict(zip(SYMBOLS, values))
    if KB(m):
        print({k: int(v) for k, v in m.items()})
```

**실행 결과**

```
True
False
{'B11': 0, 'B21': 1, 'P11': 0, 'P12': 0, 'P21': 0, 'P22': 0, 'P31': 1}
{'B11': 0, 'B21': 1, 'P11': 0, 'P12': 0, 'P21': 0, 'P22': 1, 'P31': 0}
{'B11': 0, 'B21': 1, 'P11': 0, 'P12': 0, 'P21': 0, 'P22': 1, 'P31': 1}
```

- 128개 모델 중 KB가 참인 것은 **3개**
- 세 모델 모두 P12 = 0 → **KB ⊨ ¬P₁,₂** (True)
- P22 = 1 인 모델이 있음 → **KB ⊭ ¬P₂,₂** (False)

## 10. [보충] 동치·타당성·충족 가능성과 추론 규칙

강의 목차(Outline)에는 있지만 이 PDF에는 슬라이드가 없는 부분이다. 요약(Summary)에 나오는 용어를 이해할 수 있도록 핵심만 정리한다.

### 10.1 논리적 동치, 타당성, 충족 가능성

| 개념 | 정의 | 예 |
|---|---|---|
| **논리적 동치** (equivalence), α ≡ β | 두 문장이 **같은 모델들에서** 참 (α ⊨ β 이고 β ⊨ α) | P ∧ Q ≡ Q ∧ P |
| **타당성** (validity) | **모든** 모델에서 참 = **항진명제**(tautology) | P ∨ ¬P, P ⇒ P |
| **충족 가능성** (satisfiability) | **어떤** 모델에서 참 (참이 되는 모델이 하나라도 있음) | P ∧ Q (P, Q 둘 다 참이면 참) |
| **충족 불가능** (unsatisfiable) | **어떤** 모델에서도 참이 아님 = 모순 | P ∧ ¬P |

**함의와의 관계** (중요)

- **KB ⊨ α ⇔ (KB ⇒ α)가 타당하다**
- **KB ⊨ α ⇔ (KB ∧ ¬α)가 충족 불가능하다** ← **귀류법**(모순에 의한 증명). 도출(resolution)이 이 원리를 쓴다.

**자주 쓰는 동치 법칙**

| 이름 | 동치 |
|---|---|
| 함축 제거 | α ⇒ β ≡ ¬α ∨ β |
| 쌍조건 제거 | α ⇔ β ≡ (α ⇒ β) ∧ (β ⇒ α) |
| 대우 | α ⇒ β ≡ ¬β ⇒ ¬α |
| 이중 부정 | ¬(¬α) ≡ α |
| 드모르간 | ¬(α ∧ β) ≡ ¬α ∨ ¬β, ¬(α ∨ β) ≡ ¬α ∧ ¬β |
| 분배 | α ∧ (β ∨ γ) ≡ (α ∧ β) ∨ (α ∧ γ), α ∨ (β ∧ γ) ≡ (α ∨ β) ∧ (α ∨ γ) |

### 10.2 추론 규칙과 정리 증명

진리표처럼 모델을 전부 나열하지 않고, **규칙을 적용해 문장을 직접 도출** 하는 방법이다.

| 규칙 | 형태 | 예 |
|---|---|---|
| **전건 긍정** (Modus Ponens) | α ⇒ β 와 α 로부터 β | "비가 오면 땅이 젖는다", "비가 온다" → "땅이 젖는다" |
| **연언 제거** (And-Elimination) | α ∧ β 로부터 α | |

| 방법 | 아이디어 | 성질 (Summary 기준) |
|---|---|---|
| **전방 연결** (forward chaining) | 알려진 사실에서 출발해 규칙을 적용하며 **새 사실을 계속 추가** → 질의가 나올 때까지 (데이터 주도) | **혼 절**(Horn clause)에 대해 **선형 시간**, **완전** |
| **후방 연결** (backward chaining) | 질의(목표)에서 출발해 그것을 증명하려면 무엇이 필요한지 **거꾸로** 따라감 (목표 주도) | 혼 절에 대해 선형 시간, 완전 |
| **도출** (resolution) | 문장들을 **CNF**(절들의 ∧)로 바꾸고, KB ∧ ¬α 에서 **빈 절(모순)** 을 도출 | 명제 논리에 대해 **완전** |

- **혼 절(Horn clause)**: 양의 리터럴(부정이 붙지 않은 기호)이 **최대 하나** 인 절. 예: ¬A ∨ ¬B ∨ C ≡ (A ∧ B) ⇒ C
- **CNF (Conjunctive Normal Form, 연언 표준형)**: (A ∨ ¬B) ∧ (¬C ∨ D ∨ E) 처럼 "∨로 묶인 절"을 ∧로 이은 형태

### 10.3 명제 논리의 한계

- 요약의 마지막 줄: "**명제 논리는 표현력이 부족하다**"
- 웜푸스 세계에서 "구덩이 옆에는 바람이 분다"를 쓰려면 **칸마다 문장을 하나씩** (R₄, R₅, …) 써야 한다. 4×4면 16개, 100×100이면 10,000개!
- "**모든** 칸 x에 대해, x에 바람 ⇔ x의 인접 칸에 구덩이" 처럼 **한 번에** 쓰려면 **1차 논리(first-order logic, 8장)** 가 필요하다.

## 11. 요약

- **논리적 에이전트** 는 지식 베이스에 **추론** 을 적용해 새 정보를 얻고 결정을 내린다.
- **지식 베이스(KB)** = 형식 언어로 쓴 문장들의 집합. **Tell** 로 알려 주고 **Ask** 로 묻는다 (선언적 접근).
- **웜푸스 세계**: 4×4 격자, 부분 관측·결정적·정적·이산·단일 에이전트. Stench/Breeze/Glitter/Bump/Scream 5개 센서
- 논리의 기본 개념
  - **구문(syntax)**: 문장의 형식적 구조
  - **의미(semantics)**: 모델에 대한 문장의 **참**
  - **함의(entailment)**: 한 문장이 주어졌을 때 다른 문장이 **필연적으로 참** — KB ⊨ α ⇔ M(KB) ⊆ M(α)
  - **추론(inference)**: 다른 문장들로부터 문장을 **도출** — KB ⊢ α
  - **건전성(soundness)**: 도출은 **함의된 문장만** 만들어낸다
  - **완전성(completeness)**: 도출로 **함의된 문장을 모두** 만들어낼 수 있다
- **명제 논리**: ¬, ∧, ∨, ⇒, ⇔ (우선순위 순). 모델 = 기호마다 참/거짓 배정
- **모델 검사 / TT-Entails**: 모든 모델을 열거 → 건전·완전하지만 **O(2ⁿ)**
- 웜푸스 세계에는 **부분적이고 부정된 정보를 표현** 하고 **경우를 나누어 추론** 하는 능력이 필요하다.
- [보충] 전방·후방 연결은 **혼 절** 에 대해 선형 시간·완전, **도출** 은 명제 논리에 대해 완전, 명제 논리는 **표현력이 부족** 하다 (→ 1차 논리)

에이전트는 자기 칸의 국지적 인지(바람, 악취 등)만 받으므로 부분 관측이다. 웜푸스는 움직이거나 전략적으로 행동하지 않아 사실상 지형(자연물)처럼 취급하므로 단일 에이전트다.
</details>

**Q4.** [1,1]에서 아무것도 없었고, [2,1]에서 바람, [1,2]에서 악취(바람 없음)를 감지했다. 웜푸스와 구덩이 위치를 추론하라.

<details><summary>▶ 정답 보기</summary>

- [1,2]의 악취 → 웜푸스는 [1,3] 또는 [2,2]. [2,1]에 악취가 없었으므로 [2,2]는 아님 → **웜푸스 [1,3]**
- [1,2]에 바람 없음 → [2,2]에 구덩이 없음. [2,1]의 바람은 [2,2] 또는 [3,1]의 구덩이 때문 → **구덩이 [3,1]**
</details>

**Q5.** [1,1]에서 바로 악취가 날 때의 "강요(coercion)" 전략을 설명하라.

<details><summary>▶ 정답 보기</summary>

정면 [2,1]로 화살을 쏜다. 웜푸스가 거기 있었다면 죽어서 안전해지고, 없었다면 원래 안전하다. 어느 경우든 [2,1]이 안전해진다.
</details>

**Q6.** 구문과 의미의 차이를 산술 예로 설명하라.

<details><summary>▶ 정답 보기</summary>

구문: `x + 2 ≥ y` 는 올바른 문장이고 `x2 + y >` 는 문장이 아니다(문법). 의미: `x + 2 ≥ y` 는 x=7, y=1인 세계에서 참, x=0, y=6인 세계에서 거짓(세계에서의 참).
</details>

**Q7.** KB ⊨ α 의 정의를 "세계"와 "모델 집합" 두 가지 방식으로 쓰라.

<details><summary>▶ 정답 보기</summary>

- KB가 참인 **모든 세계** 에서 α도 참이다.
- **M(KB) ⊆ M(α)**
</details>

**Q8.** "자이언츠가 이겼거나 레즈가 이겼다" ⊨ "자이언츠가 이겼다" 는 성립하는가?

<details><summary>▶ 정답 보기</summary>

성립하지 않는다. 레즈만 이긴 세계에서 KB는 참이지만 α는 거짓이기 때문이다.
</details>

**Q9.** 4장 모델 검사에서 KB가 참인 모델은 몇 개이고, [1,2]는 안전하다고 증명되는데 [2,2]는 안 되는 이유는?

<details><summary>▶ 정답 보기</summary>

3개. 세 모델 모두 [1,2]에 구덩이가 없으므로 KB ⊨ α₁. 하지만 그중 2개는 [2,2]에 구덩이가 있으므로 KB ⊭ α₂.
</details>

**Q10.** 건전성과 완전성을 ⊢, ⊨ 기호로 정의하고, 각각을 위반하면 어떤 문제가 생기는지 쓰라.

<details><summary>▶ 정답 보기</summary>

- 건전성: KB ⊢ α ⇒ KB ⊨ α. 위반하면 함의되지 않는 거짓 결론을 도출한다.
- 완전성: KB ⊨ α ⇒ KB ⊢ α. 위반하면 함의되는 결론을 놓친다.
</details>

**Q11.** 다음 문장에 괄호를 쳐서 우선순위를 명확히 하라: `¬A ∨ B ∧ C ⇒ D`

<details><summary>▶ 정답 보기</summary>

((¬A) ∨ (B ∧ C)) ⇒ D
</details>

**Q12.** P = false, Q = true 일 때 P ⇒ Q, Q ⇒ P, P ⇔ Q 의 값은?

<details><summary>▶ 정답 보기</summary>

P ⇒ Q = **true** (전건 거짓), Q ⇒ P = **false** (참 ⇒ 거짓), P ⇔ Q = **false** (값이 다름)
</details>

**Q13.** P₁,₂ = false, P₂,₂ = true, P₃,₁ = false 인 모델에서 `¬P₁,₂ ∧ (P₂,₂ ∨ P₃,₁)` 의 값은?

<details><summary>▶ 정답 보기</summary>

¬false ∧ (true ∨ false) = true ∧ true = **true**
</details>

**Q14.** R₅: B₂,₁ ⇔ (P₁,₁ ∨ P₂,₂ ∨ P₃,₁) 을 ⇒ 가 아니라 ⇔ 로 쓰는 이유는?

<details><summary>▶ 정답 보기</summary>

"구덩이가 있으면 바람"과 "바람이 있으면 근처에 구덩이" 두 방향이 모두 필요하기 때문이다. 바람을 관측했을 때 구덩이 후보를 추론하는 것은 반대 방향(바람 ⇒ 구덩이)이다.
</details>

**Q15.** 기호가 20개인 KB에 TT-Entails를 적용하면 검사하는 모델은 몇 개인가? 공간 복잡도는?

<details><summary>▶ 정답 보기</summary>

2²⁰ = 1,048,576개 (약 100만). 깊이 우선이므로 공간은 O(n) = 기호 수에 비례.
</details>

**Q16.** TT-CHECK-ALL에서 KB가 거짓인 모델에 대해 `true`를 반환하는 이유는?

<details><summary>▶ 정답 보기</summary>

함의는 "KB가 참인 모든 세계에서 α가 참"인지만 따진다. KB가 거짓인 세계는 반례가 될 수 없으므로 통과(true)시킨다.
</details>

**Q17.** [보충] 다음을 분류하라 (타당 / 충족 가능 / 충족 불가능): ① P ∨ ¬P ② P ∧ ¬P ③ P ⇒ Q

<details><summary>▶ 정답 보기</summary>

① 타당(항상 참) ② 충족 불가능(항상 거짓) ③ 충족 가능(타당하지는 않음, P=참·Q=거짓일 때 거짓)
</details>

**Q18.** [보충] 명제 논리의 "표현력이 부족하다"는 것을 웜푸스 세계로 설명하라.

<details><summary>▶ 정답 보기</summary>

"구덩이 옆 칸에는 바람이 분다"는 일반 규칙을 한 번에 쓸 수 없어 칸마다 R₄, R₅ 같은 문장을 따로 써야 한다. "모든 칸에 대해"를 표현하려면 1차 논리가 필요하다.
</details>

|---|---|---|

| Inference engine | 추론 엔진 | KB에서 새 문장을 이끌어내는 도메인 독립 알고리즘 |
| Declarative approach | 선언적 접근 | 무엇이 참인지 알려 주고 행동은 추론하게 함 |
| Tell / Ask | 알려 주기 / 묻기 | KB에 문장 추가 / KB에 질의 |
| Knowledge level | 지식 수준 | 에이전트가 무엇을 아는가의 관점 |
| Wumpus | 웜푸스 | 동굴 속 괴물 (예제 환경) |
| Pit / Breeze / Stench | 구덩이 / 바람 / 악취 | |
| Coercion | 강요 전략 | 어느 경우든 안전해지도록 행동 (화살 쏘기) |
| Syntax | 구문 | 올바른 문장의 형식 |
| Semantics | 의미 | 세계(모델)에서 문장의 참·거짓 |
| Model | 모델 | 참·거짓을 평가할 수 있는 가능한 세계 |
| M(α) | α의 모델 집합 | α가 참인 모든 모델 |
| Entailment (⊨) | 함의 | KB가 참인 모든 모델에서 α도 참 |
| Model checking | 모델 검사 | 모든 모델을 나열해 함의를 확인 |
| Inference (⊢) | 추론 / 도출 | 절차로 문장을 이끌어냄 |
| Soundness | 건전성 | 함의된 문장만 도출 |
| Completeness | 완전성 | 함의된 문장은 모두 도출 가능 |

| BNF | 배커스–나우르 형식 | 문법 정의 표기법 |
| Truth table | 진리표 | 모든 경우의 참·거짓을 나열한 표 |
| Validity / Satisfiability | 타당성 / 충족 가능성 | 모든 모델에서 참 / 어떤 모델에서 참 |
| Horn clause | 혼 절 | 양의 리터럴이 최대 하나인 절 |
