## 2. 장별 출제 범위와 복습 링크

### 1장 · LLM 이해하기 → [1장 노트](./01-understanding_LLM.md)

| 절 | 주제 | 핵심 한 줄 |
|---|---|---|
| 1절 | 다음 토큰 예측 | 앞부분만 주고 다음에 올 토큰 하나를 맞히는 훈련 과제 |
| 6절 | 사전 훈련·미세 튜닝 | 레이블 없는 대규모 텍스트로 사전 훈련 → 레이블 있는 작은 데이터로 미세 튜닝 |
| 7절 | 자기 지도 학습 | 레이블을 사람이 아니라 **입력 데이터 자체에서** 생성 |
| 9절 | BERT와 GPT | BERT는 **인코더**(앞뒤 참조)·분류, GPT는 **디코더**(앞만 참조)·생성 |
| 10절 | 제로-샷·퓨-샷 | 재훈련 없이 프롬프트만으로 새 작업 수행 — 예시 없음 / 예시 몇 개 |

### 2장 · 텍스트 토큰화 → [2장 노트](./02-tokenize.md)

| 절 | 주제 | 핵심 한 줄 |
|---|---|---|
| 1~3절 | 임베딩 | 이산적인 객체를 **연속적인 벡터 공간의 한 점** 으로 매핑하는 변환 |
| 4절 | 처리 파이프라인 | 텍스트 → 토큰 → 토큰 ID → 토큰 임베딩 → 모델 |
| 6절 | 어휘사전 | 토큰과 고유한 정수(토큰 ID)의 대응 — **의미 정보는 담지 않음** |
| 9·11절 | 특수 토큰 | `<\|unk\|>` 는 사전에 없는 단어, `<\|endoftext\|>` 는 텍스트 사이의 경계 |
| 12~13절 | BPE | 자주 붙어 나오는 조합을 병합 — 모르는 단어는 **부분단어** 로 나눔 |

### 3장 · 데이터 샘플링과 임베딩 → [3장 노트](./03-sampling_embedding.md)

| 절 | 주제 | 핵심 한 줄 |
|---|---|---|
| 2절 | 입력 x와 타깃 y | y는 x를 **한 토큰 뒤로 민 것** — y를 맞히는 것이 다음 토큰 예측 |
| 3~4절 | 데이터셋·데이터 로더 | 데이터셋은 입력·타깃 **행 추출**, 데이터 로더는 **배치로 묶음** |
| 5절 | 스트라이드 | 다음 입력이 **몇 토큰 뒤에서 시작** 하는지를 정함 |
| 7절 | 임베딩 층 | 토큰 ID 번호의 **행을 읽어 반환하는 룩업** 연산 |
| 8절 | 원-핫 인코딩 | 원-핫 벡터 × 가중치 행렬 = 룩업과 같은 결과 |
| 9~10절 | 위치 임베딩 | 룩업은 위치를 모름 → 절대 위치 / 상대 위치 임베딩 |
| 11~12절 | 입력 임베딩 | 토큰 임베딩 + 위치 임베딩 (**차원이 같아야 함**) |

### 4장 · 셀프 어텐션 → [4장 노트](./04-self_attention.md)

| 절 | 주제 | 핵심 한 줄 |
|---|---|---|
| 2~4절 | RNN의 한계 | 디코더가 **최종 은닉 상태 하나에만 의존** → 어텐션의 계기 |
| 6절 | 문맥 벡터 | 다른 토큰의 정보까지 통합해 다시 표현한 벡터 |
| 8~11절 | 간소화 3단계 | 점곱으로 점수 ω → 소프트맥스로 가중치 α → 가중 합으로 문맥 벡터 z |
| 15·19절 | 쿼리·키·값 | 쿼리는 기준, 키는 비교 대상, 값은 문맥 벡터로 조합되는 정보 |
| 16절 | 두 가중치 구별 | W_q·W_k·W_v는 **훈련으로 갱신**, 어텐션 가중치 α는 **입력마다 계산** |
| 18절 | √dₖ 스케일링 | 점수 차가 커져 소프트맥스가 쏠리고 그레이디언트가 사라지는 것을 완화 |

### 5장 · 코잘·멀티 헤드 어텐션 → [5장 노트](./05-causal_multihead_attention.md)

| 절 | 주제 | 핵심 한 줄 |
|---|---|---|
| 2절 | 코잘 어텐션 | 미래 토큰을 가려 현재 위치까지만 참조 — 정답을 미리 보지 않게 |
| 4절 | −∞ 마스킹 | 소프트맥스 전에 −∞로 바꾸면 가중치 0, **재정규화 불필요** |
| 5·6절 | 드롭아웃 | 훈련 중 가중치 일부를 0으로 — 과대적합 감소, **추론에서는 끔** |
| 10절 | 멀티 헤드 | 헤드마다 다른 쿼리·키·값 가중치로 어텐션을 여러 번 수행 |
| 12·14절 | 두 구현 방식 | 래퍼 방식은 헤드를 차례로, 가중치 분할 방식은 한 행렬로 함께 계산 |

## 3. 교수님 공개 연습 문제 10개 ⭐

> 공지에 "**각 장 하단의 연습 문제 시험 출제 예정**"이라고 되어 있으므로 반드시 풀어 본다.

**1장-1.** 사전 훈련 단계에서 사용하는 데이터는?
① 레이블 있는 작은 타깃 데이터셋이다 ② 지시와 정답의 쌍이다 ③ 레이블 없는 대규모 원시 텍스트이다 ④ 텍스트와 클래스 레이블이다

<details><summary>▶ 정답</summary>

**③** — ②는 지시 미세 튜닝, ①·④는 분류 미세 튜닝의 데이터다.
</details>

**1장-2.** 자기 지도 학습에서 레이블을 얻는 방식은?
① 사람이 레이블을 수집한다 ② 레이블을 입력 데이터 자체에서 생성한다 ③ 도메인 전문가가 수동으로 설계한다 ④ 신경망이 원문을 받아 특성을 스스로 생성·학습한다

<details><summary>▶ 정답</summary>

**②** — ④는 딥러닝의 **특성** 자동 추출(1장 3절)에 대한 설명이라 함정이다. (공지: 오답 선지 수정, 정답 변경 없음)
</details>

**2장-1.** 임베딩에 대한 설명으로 **틀린** 것은?
① 이산적인 단어를 연속적인 벡터 공간의 점으로 대응시켜 수치 연산에 쓸 수 있게 한다 ② 임베딩 벡터의 차원은 어휘사전의 토큰 수와 같아야 한다 ③ 텍스트, 오디오, 비디오는 각각 별도의 임베딩 모델로 벡터로 변환한다 ④ 임베딩 벡터의 값은 처음에 정한 값이 아니라 훈련을 거치며 최적화된다

<details><summary>▶ 정답</summary>

**②** — 임베딩 차원(GPT-2 small 768)은 설계자가 정하는 값이고, 어휘사전 크기(50,257)는 임베딩 행렬의 **행 수** 다.
</details>

**2장-2.** `<|endoftext|>` 토큰의 역할과 여러 문서로 훈련할 때 두는 위치에 대한 설명으로 옳은 것은?
① 사전에 없는 단어를 만나면 그 자리를 대신해 토큰 ID 조회 오류를 막는다 ② 각 문서의 맨 앞에만 두어 시작 위치를 알리고, 끝 표시는 별도의 토큰이 맡는다 ③ `<|endoftext|>` 는 텍스트의 끝이라는 뜻으로, 서로 무관한 텍스트 사이의 경계를 표시한다 ④ 경계를 표시하지 않아도 모델이 이어 붙인 두 문서를 서로 무관한 텍스트로 알아서 구분한다

<details><summary>▶ 정답</summary>

**③** — ①은 `<|unk|>` 의 역할이다.
</details>

**3장-1.** Dataset과 DataLoader의 역할을 올바르게 설명한 것은?
① Dataset은 한 배치에 몇 행을 담을지 정하고, DataLoader는 입력·타깃 쌍의 총 개수를 반환한다 ② Dataset은 토큰 ID를 임베딩 벡터로 변환하고, DataLoader는 위치 임베딩을 더한다 ③ Dataset은 입력 행의 순서를 무작위로 섞고, DataLoader는 슬라이딩 윈도를 적용한다 ④ Dataset은 입력·타깃 쌍을 한 행씩 추출하는 역할을 하고, DataLoader는 그 행들을 배치 텐서로 묶는 역할을 한다

<details><summary>▶ 정답</summary>

**④** — ①·③은 역할을 서로 뒤바꾼 함정이다 (배치 크기·섞기는 DataLoader, 슬라이딩 윈도·`__len__` 은 Dataset).
</details>

**3장-2.** 임베딩 층에서 원-핫 벡터와의 행렬 곱셈 대신 룩업 연산을 사용하는 이유는?
① 가중치 행렬에서 토큰 ID에 해당하는 행을 바로 찾는 룩업은 원-핫 벡터와의 행렬 곱셈과 같은 결과를 더 효율적으로 낸다 ② 룩업을 사용하면 같은 토큰이라도 등장 위치마다 자동으로 다른 임베딩 벡터가 만들어진다 ③ 룩업을 사용하면 임베딩 가중치 행렬은 훈련 과정에서 더 이상 갱신되지 않는다 ④ 룩업은 토큰 ID를 임베딩 벡터로 변환하면서 위치 정보까지 함께 추가한다

<details><summary>▶ 정답</summary>

**①** — 룩업은 위치를 모르고(②·④ 틀림), 행렬 곱과 같은 결과라 역전파로 갱신된다(③ 틀림).
</details>

**4장-1.** 문맥 벡터란?
① 원문을 끝까지 처리한 뒤의 값인 최종 은닉 상태이다 ② 각 입력을 얼마나 반영할지 정하는 값이다 ③ 같은 시퀀스에 있는 다른 토큰의 정보까지 통합해 다시 표현한 벡터이다 ④ 벡터 두 개를 결합해 만든 숫자 하나인 스칼라이다

<details><summary>▶ 정답</summary>

**③** — ①은 RNN 최종 은닉 상태, ②는 어텐션 가중치 α, ④는 점곱 결과(스칼라)다.
</details>

**4장-2.** 점수를 √dₖ로 나누지 않아 점수들 사이의 차이가 크게 벌어지면 생기는 문제는?
① 소프트맥스 출력이 한쪽에 쏠리고 그 지점에서 그레이디언트가 0에 가까워져 훈련이 정체된다 ② 어느 토큰에 주의를 기울일지를 어텐션 단계에서 학습할 수 없다 ③ 같은 벡터가 쿼리와 키 역할을 겸해 점수 행렬이 대칭이 된다 ④ 앞쪽 정보나 멀리 떨어진 단어 사이의 관계가 충분히 남지 않는다

<details><summary>▶ 정답</summary>

**①** — ②·③은 간소화 버전의 한계, ④는 RNN의 한계다.
</details>

**5장-1.** 코잘 어텐션에 대한 설명으로 옳은 것은?
① 각 토큰의 문맥 벡터를 구할 때 입력 토큰 전체를 참조한다 ② 각 토큰의 문맥 벡터에는 자기 자신과 이전 토큰의 정보만 반영된다 ③ 같은 입력을 여러 헤드가 각자 독립적으로 처리한 뒤 결과를 하나로 합친다 ④ 추론 단계에서는 적용하지 않고 훈련 중에만 적용한다

<details><summary>▶ 정답</summary>

**②** — ①은 4장 셀프 어텐션, ③은 멀티 헤드, ④는 드롭아웃에 대한 설명이다 (코잘 마스크는 추론에서도 적용). (공지: 오답 선지 수정, 정답 변경 없음)
</details>

**5장-2.** 소프트맥스 이전에 미래 토큰의 점수를 −∞로 마스킹하면 재정규화가 필요 없는 이유는?
① e^(−∞) = 0이므로 마스킹한 위치는 가중치가 0이 되고 행의 합에도 더해지지 않기 때문이다 ② 하삼각 마스크를 가중치와 같은 위치끼리 곱해 미래 토큰의 가중치만 0이 되기 때문이다 ③ 마스크를 버퍼로 등록해 훈련으로 값이 바뀌지 않기 때문이다 ④ 실제 토큰 수만큼 마스크의 왼쪽 위 부분만 슬라이싱해 사용하기 때문이다

<details><summary>▶ 정답</summary>

**①** — ②는 재정규화가 **필요한** 3절 방법이고, ③·④는 구현 세부라 이유가 아니다.
</details>

### 4.2 계산 문제 모음 (손으로 풀어 보기)

| 문항 | 문제 | 답 | 풀이 |

### 4.3 자주 나온 함정 선지

| 함정 | 바른 내용 |
|---|---|
| "임베딩 차원은 어휘사전 크기와 같아야 한다" | 차원은 설계자가 정함. 어휘사전 크기는 **행 수** |
| "토큰 ID가 가까우면 의미도 비슷하다" | ID는 식별 번호일 뿐 **의미 정보 없음** (Q30) |
| "`<\|unk\|>` 는 문서 끝, `<\|endoftext\|>` 는 미등록 단어" | 역할이 **뒤바뀐** 선지 (Q35) |
| "룩업은 위치 정보도 더한다 / 훈련으로 갱신되지 않는다" | 룩업은 위치를 모르고, 역전파로 **갱신된다** |
| "코잘 마스크는 훈련 중에만 적용" | 그건 **드롭아웃**. 코잘 마스크는 추론에서도 유지 (Q87) |
| "미래 점수를 0으로 바꾸면 차단된다" | e⁰ = 1 이라 가중치가 생김 → **−∞** 로 바꿔야 함 (Q90) |
| "드롭아웃으로 미래를 차단할 수 있다" | 무작위라 100% 차단을 보장 못 함 (Q96) |
| "W_q·W_k·W_v와 α 모두 훈련으로 갱신" | W는 훈련 파라미터, α는 **입력마다 계산** (Q75·Q76) |
| "BERT 디코더, GPT 인코더" / "BERT 앞만, GPT 앞뒤" | **BERT 인코더·양방향·분류, GPT 디코더·앞만·생성** |
| "Dataset이 배치를 묶고 섞는다" | 배치·섞기는 **DataLoader**, 행 추출은 **Dataset** |

> ⚠️ Q79 해설의 "점수 분산을 1로 유지"는 요약본(4장 18절)에 없는 표현이다. 요약본은 "dₖ가 커질수록 점곱 값이 커지기 쉬워 √dₖ로 나눠 크기를 조절한다"까지만 설명한다. 정답 선택에는 영향이 없다.
