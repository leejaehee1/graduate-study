## 1. LLM의 정의

> **LLM (Large Language Model, 대규모 언어 모델)**: 사람이 쓴 텍스트를 **이해·생성·응답**하도록 고안된 **심층 신경망**. 훈련 데이터는 대용량 텍스트이며, 그중 상당 부분이 인터넷에 공개된 글이다.

### 1.1 '대규모'의 두 축

| 축 | 설명 |
|---|---|
| **파라미터의 수** | 파라미터 = 신경망의 **가중치**, 즉 입력값에 곱해지는 숫자. 훈련 중 계속 조정되며 **모델이 배운 모든 것이 저장되는 자리**. GPT-3 기준 **1,750억 개** |
| **훈련 데이터의 양** | 파라미터 수만 늘리면 그 안에 담을 지식이 없다. **두 값이 함께 커진 것**이 '대규모'의 의미 |

> 💡 **비유**: 파라미터는 "뇌의 용량", 데이터는 "읽은 책의 양". 용량만 크고 책을 안 읽으면 소용없고, 책만 많고 용량이 작으면 다 담지 못한다.

### 1.2 훈련 과제: 다음 토큰 예측 ⭐

> 문장의 **앞부분까지만** 주고 **그다음에 올 토큰 하나**를 맞히게 하는 과제

- 언어가 **순차적 데이터**라는 특징 덕분에, 이 과제 하나로 **맥락·구조·관계**를 함께 학습한다.

**예시**: *"나는 통장을 새로 만들려고 ___에 갔다"*
- '은행'을 맞히려면 앞의 '통장', '만들다'와의 **의미 관계를 이미 파악**한 상태여야 한다.
- → **단어 하나를 맞히는 일이 곧 문맥 파악**인 이유
- 훈련 목표는 이것 하나뿐이었는데 **번역·요약·질의응답까지** 별도 훈련 없이 함께 학습되었다. **많은 연구자가 예상하지 못한 결과**다.

### 1.3 토큰 (Token)

| 용어 | 정의 |
|---|---|
| **토큰** | 모델이 텍스트를 읽는 **단위**이자 훈련 데이터의 **양을 재는 단위** |
| **토크나이저** | 텍스트를 토큰으로 나누는 도구 |
| **어휘 사전 (vocabulary)** | 토크나이저가 아는 토큰의 목록 |

- 대체로 **단어 하나 ≈ 토큰 하나**이고 구두점도 하나로 세므로 흔히 "다음 **단어** 예측"이라 부르지만, 실제 예측 단위는 **토큰**이다.
- 사전에 통째로 등록된 흔한 영어 단어 → **1토큰**
- 등록되지 않은 표기 → **잘게 쪼개짐**

> ### 🧪 실습 A. LLM이 보는 단위 = 토큰
>
> ```python
> import tiktoken
>
> tokenizer = tiktoken.get_encoding("gpt2")   # GPT-2가 사용한 BPE 토크나이저
> print("어휘 사전 크기(vocab size):", tokenizer.n_vocab)   # 50257
>
> text = "LLMs learn by predicting the next word."
> ids = tokenizer.encode(text)
> print(f"토큰 ID: {ids}")
> print(f"토큰 개수: {len(ids)}")
> for i in ids:
>     print(f"  {i:>6}  ->  {tokenizer.decode([i])!r}")
> ```
>
> **실행 결과**
>
> | 토큰 ID | 사람이 보는 조각 |
> |---|---|
> | 3069 | `'LL'` |
> | 10128 | `'Ms'` |
> | 2193 | `' learn'` |
> | 416 | `' by'` |
> | 25539 | `' predicting'` |
> | 262 | `' the'` |
> | 1306 | `' next'` |
> | 1573 | `' word'` |
> | 13 | `'.'` |
>
> **관찰 포인트**
> - 어휘 사전 크기는 **50,257**
> - LLM은 왼쪽의 **정수(토큰 ID) 시퀀스**로 읽는다. 오른쪽 글자는 사람이 보기 위한 것
> - `LLMs` 는 흔한 단어가 아니라서 `LL` + `Ms` 두 토큰으로 **쪼개졌다**
> - `' learn'` 처럼 **앞의 공백까지 토큰에 포함**된다
>
> ### 🧪 실습 A-2. 문장 길이와 언어에 따른 토큰 수
>
> ```python
> samples = [
>     "Hello!",
>     "Breakfast is the most important meal of the day.",
>     "This is an example of how concise I can be.",
>     "밑바닥부터 만들면서 배우는 LLM",
> ]
> for s in samples:
>     print(f"토큰 {len(tokenizer.encode(s)):>2}개  |  {s}")
> ```
>
> | 토큰 수 | 문장 |
> |---|---|
> | 2 | `Hello!` |
> | 11 | `Breakfast is the most important meal of the day.` |
> | 11 | `This is an example of how concise I can be.` |
> | **37** | `밑바닥부터 만들면서 배우는 LLM` |
>
> 💡 한글은 글자 수가 훨씬 적은데도 토큰이 **37개**나 된다. GPT-2 토크나이저는 영어 위주로 만들어져서 한글 단어가 사전에 거의 없어 **바이트 단위로 잘게 쪼개지기** 때문이다. (자세한 원리는 2장 BPE에서)

### 1.4 생성 AI와 활용 범위

- **생성 AI (GenAI)**: 텍스트를 **생성**하는 능력 때문에 LLM을 이렇게 부르기도 한다. 단, 둘은 **같은 범주가 아니다** (2절 참고).
- **활용 범위**
  - 기본 작업: **기계 번역, 텍스트 생성, 요약, 감성 분석**(글의 긍정·부정 판별)
  - 확장: 소설·기사·**코드 생성**, **챗봇·가상 비서**(ChatGPT, Gemini), **의료·법률** 등 전문 영역의 문서 검색과 질의응답
  - 공통 기반은 **비정형 텍스트의 분석과 이해** → 텍스트를 다루는 작업이라면 대체로 적용 대상

## 2. AI 분야 안에서의 위치

```
┌─────────────────────────────── 인공지능 (AI) ───────────────────────────────┐
│  규칙 기반 시스템 포함                                                          │
│   ┌───────────────────────── 머신러닝 ─────────────────────────┐              │
│   │  데이터로부터 학습                                          │              │
│   │   ┌─────────────────── 딥러닝 ───────────────────┐         │              │
│   │   │  은닉층 1개 이상 (3개 이상의 층)               │    ┌────┼──────────┐   │
│   │   │   ┌──────────── LLM ────────────┐          │    │    │ 생성 AI    │   │
│   │   │   │  딥러닝을 텍스트에 특화       │ ◀── 겹침 ──▶│    │ (이미지·   │   │
│   │   │   └─────────────────────────────┘          │    │    │  오디오 등)│   │
│   │   └─────────────────────────────────────────────┘    └────┼──────────┘   │
│   └────────────────────────────────────────────────────────────┘              │
└──────────────────────────────────────────────────────────────────────────────┘
```

| 분야 | 정의 | 경계선 |
|---|---|---|
| **인공지능 (AI)** | 사람 수준 지능이 필요한 작업의 수행 | 학습이 **필수는 아님** → 규칙 기반 시스템도 포함 |
| **머신러닝** | 명시적 프로그래밍 없이 **데이터로부터 학습** | 규칙을 **사람이 쓰느냐 / 데이터에서 뽑아내느냐** |
| **딥러닝** | 입력층·은닉층·출력층을 합해 **3개 이상의 층** (= 은닉층 1개 이상) | 신경망의 깊이 |
| **LLM** | 딥러닝을 **텍스트에 특화** | 사람이 쓴 것 같은 텍스트의 생성·처리 |

### 생성 AI와 LLM의 관계 ⭐

- 생성 AI는 위 계층들과 **나누는 기준이 다르다**.
  - 위 계층: **무엇을 다루는가**
  - 생성 AI: **새로 만드는가** → 그래서 텍스트뿐 아니라 **이미지·오디오**까지 포함
- 따라서 LLM과 생성 AI는 **포함 관계가 아니라 교차(일부만 겹침) 관계**다.
  - LLM이 **글을 써내는** 작업 → 겹침 (둘 다 해당)
  - LLM이 **스팸 여부를 판정**하는 작업 → 고르기만 하므로 새로 만드는 것이 없음 → **생성 AI 아님**

## 3. 전통적인 머신러닝 vs 딥러닝: 특성 추출

**전제**: 신경망이든 아니든 **모델의 입력은 숫자**여야 한다.

| 용어 | 의미 | 예 (스팸 분류) |
|---|---|---|
| **특성 (feature)** | 원문에서 판단에 쓸 값을 뽑아낸 것 | '경품'·'무료'의 등장 빈도 |
| **레이블 (label)** | 각 데이터에 붙인 정답 표시 | 스팸이다 / 아니다 |

두 방식이 갈리는 지점은 **"특성을 누가 만드는가"** 이다.

| 항목 | 전통적인 머신러닝 | 딥러닝 |
|---|---|---|
| **특성 추출** | **도메인 전문가가 수동 설계** ('경품'·'무료' 빈도, 의심 링크 유무 등) | **신경망이 원문을 받아 스스로** 생성·학습. 숫자 변환은 여전히 일어나지만 그 변환을 **사람이 설계하지 않음** |
| **레이블** | 사람이 수집 | **사람이 수집** ← 딥러닝이 자동화한 것은 **특성이지 레이블이 아님!** |

- 전통 방식의 성능은 **특성 설계에 종속**된다. 전문가가 빠뜨린 단서는 모델에 전달되지 않는다.
- 문맥·어순·반어법은 **숫자 몇 개로 요약되지 않는다** → 언어처럼 좋은 특성을 정의하기 어려운 데이터일수록 딥러닝의 이득이 크다 → **NLP에서 딥러닝이 지배적이 된 이유**

## 4. LLM 이전과 이후의 NLP

| 작업 | 규칙으로 가능? | 설명 |
|---|---|---|
| **분류** | ✅ 감당 가능 | 정해진 몇 개의 답 중 하나를 고르는 문제. 예: 스팸 감지 |
| **생성** | ❌ 감당 불가 | 가능한 출력이 **사실상 무한**하고, 어떤 단어가 적절한지가 **앞뒤 문맥 전체**에 달려 있음 → 이전 접근이 무너지는 지점 |

- **범용성의 차이**: 이전 모델은 분류용·번역용처럼 **작업 전용 설계**. LLM은 **하나의 모델이 다양한 작업**을 수행
- **전환의 두 요인**: **트랜스포머 구조** + **방대한 훈련 데이터**
- ⚠️ LLM이 언어를 "이해한다"고 할 때의 이해 = **일관성 있고 맥락에 맞게 텍스트를 처리·생성하는 능력**. 사람과 같은 **의식이나 이해력을 뜻하지 않는다**.

## 5. 직접 만드는 이유

| 이유 | 설명 |
|---|---|
| **메커니즘과 한계의 이해** | 어떤 입력에서 틀리는지, 왜 그런 답이 나오는지 짚어낼 수 있음 → LLM 도입·구조 결정의 판단 근거 |
| **실무 기술로의 전이** | 공개 모델을 자기 분야 데이터로 **재훈련(사전 훈련)** 하거나 용도에 맞게 **조정(미세 튜닝)** 하는 작업에 그대로 적용. 도구는 **PyTorch** — 오늘날 대부분의 LLM이 이 라이브러리로 제작됨 |
| **특화 모델의 경쟁력** | 특정 도메인에 특화된 LLM이 범용 LLM을 앞서는 사례: 금융 특화 **BloombergGPT**, 의료 질의응답 특화 모델 등. "범용 1등 모델이 모든 문제의 답은 아니다" |

### 맞춤형 LLM의 네 가지 장점 ⭐

1. **데이터 개인정보 보호**: 외부 업체의 LLM → 데이터가 업체 서버로 전송됨. 자체 모델 → 데이터가 조직 밖으로 나가지 않음
2. **온디바이스 배포**: 규모를 줄인 모델은 랩톱·스마트폰에 직접 탑재 가능
3. **응답 시간과 비용**: 장치에서 직접 실행하면 네트워크 왕복이 사라져 **지연 감소**, 서버 인프라 **비용 절감**
4. **완전한 자율성**: 모델 통제권이 개발자에게 있어 **갱신과 수정이 자유로움**

## 6. 두 단계 훈련: 사전 훈련과 미세 튜닝

### 왜 두 단계로 나누는가?

- **레이블 데이터**: 사람이 하나하나 붙여야 하므로 **크게 만들 수 없다** (비쌈)
- **레이블 없는 텍스트**: 인터넷에 **사실상 무한** (무료)
- → 언어 이해에 필요한 **방대한 학습은 무료 데이터로**, 비싼 레이블은 **작업 적응에만** 투입하는 설계

| 단계 | 데이터 | 학습 목표 | 결과 |
|---|---|---|---|
| **① 사전 훈련 (pre-training)** | **레이블 없는** 대규모 원시 텍스트 (서식 문자 제거 등 필터링은 거침) | **다음 토큰 예측** | **파운데이션 모델** (베이스 모델) |
| **② 미세 튜닝 (fine-tuning)** | **레이블 있는** 작은 타깃 데이터셋 | 지시 수행 또는 분류 | 지시 수행 / 분류 작업에 맞춰진 LLM |

```
 대규모 원시 텍스트 ──[사전 훈련]──▶ 파운데이션 모델 ──[미세 튜닝]──▶ 챗봇 / 분류기
   (레이블 X, 무한)    다음 토큰 예측     (텍스트 완성)     (레이블 O, 소량)
```

## 7. 자기 지도 학습 (Self-supervised Learning)

레이블 없이도 훈련이 가능한 원리다.

| 방식 | 레이블은 어디서? |
|---|---|
| 일반적인 **지도 학습** | **사람이** 수집 |
| **자기 지도 학습** | **입력 데이터 자체에서** 생성. 텍스트는 단어가 순서대로 이어진 데이터이므로 **각 위치의 다음 단어가 그대로 정답** |

- **즉석 생성**: 레이블을 미리 만들어 두지 않고 **훈련 중 그 자리에서** 생성 → 별도 정리 작업 없이 텍스트만으로 훈련 시작
- 대규모 원시 텍스트가 그대로 훈련 데이터가 되는 것 → **사전 훈련 단계가 성립하는 원리**
- GPT-3의 데이터셋에도 사람이 손댄 것은 **필터링뿐**이며 **레이블 작업은 없다**.

> ### 🧪 실습 B. 다음 단어 예측 = 자기 지도 학습
>
> 한 문장에서 (입력, 정답) 쌍이 **공짜로** 여러 개 만들어지는 과정:
>
> ```python
> sentence = "The model is simply trained to predict the next word"
> words = sentence.split()
>
> for i in range(1, len(words)):
>     context = " ".join(words[:i])   # 지금까지 나온 단어 (입력)
>     target = words[i]              # 바로 다음 단어 (정답/레이블)
>     print(f"  입력: {context:<48} ->  정답: {target}")
> ```
>
> **실행 결과**
>
> | 입력 (context) | 정답 (target) |
> |---|---|
> | The | model |
> | The model | is |
> | The model is | simply |
> | The model is simply | trained |
> | The model is simply trained | to |
> | The model is simply trained to | predict |
> | The model is simply trained to predict | the |
> | The model is simply trained to predict the | next |
> | The model is simply trained to predict the next | word |
>
> 💡 단어 10개짜리 문장 하나에서 **학습 예제 9개**가 사람 손 없이 만들어졌다. 이것이 인터넷의 원시 텍스트를 그대로 훈련에 쓸 수 있는 이유다. (3장의 **슬라이딩 윈도**가 이것을 토큰 단위로 구현한 것)

## 8. 파운데이션 모델과 미세 튜닝

### 8.1 파운데이션 모델의 두 능력

| 능력 | 설명 |
|---|---|
| **텍스트 완성** | 쓰다 만 문장의 이어 쓰기 → 훈련 과제 **그대로**의 수행 |
| **제한적 퓨-샷 학습** | 예시 두어 개만으로 규칙을 파악한 뒤 새 작업 수행 → 훈련 목표에 없던 능력이라 **'제한적'** |

### 8.2 미세 튜닝 두 종류

| 종류 | 데이터셋 구성 | 특징 |
|---|---|---|
| **지시 미세 튜닝** (instruction fine-tuning) | **지시와 정답의 쌍** | 파운데이션 모델은 문장을 이어 쓸 뿐 **명령을 따르도록 배운 적이 없음**. 그 차이를 메우는 훈련 → **ChatGPT가 지시를 따르게 된 이유** |
| **분류 미세 튜닝** (classification fine-tuning) | **텍스트와 클래스 레이블** | 정해진 범주 중 하나 선택. 언어를 읽는 능력은 사전 훈련에서 확보 완료 → **범주를 나누는 기준만 학습** |

> 💡 **[보충] 예시로 보는 차이**
> - 파운데이션 모델에 "프랑스의 수도는?" 이라고 입력하면 → "독일의 수도는? 이탈리아의 수도는?" 처럼 **비슷한 문장을 이어 쓸** 수도 있다.
> - 지시 미세 튜닝된 모델 → "파리입니다." 라고 **답한다**.

## 9. 트랜스포머 (Transformer)

### 9.1 기원

- **2017년 논문 "Attention Is All You Need"**
- **언어 모델이 아니라 기계 번역**을 목적으로 제안된 구조
- **인코더**와 **디코더** 두 서브모듈로 구성

```
        "This is an example"                          "Das ist ein" (지금까지 생성한 출력)
                │                                              │
                ▼                                              ▼
        ┌───────────────┐        임베딩 전달             ┌───────────────┐
        │   인코더       │ ───────────────────────────▶ │    디코더      │
        │ (입력 전체 참조)│                              │                │
        └───────────────┘                              └───────┬───────┘
                                                               ▼
                                                         "Beispiel" (다음 토큰 1개)
                                                               │
                                                  출력에 이어 붙여 다시 디코더 입력으로 ↺
```

| 구성 요소 | 역할 |
|---|---|
| **인코더** | 입력 텍스트 **전체를 참조**해 문맥 정보를 담은 수치 표현, 즉 **임베딩**으로 변환 (This is an example → 임베딩) |
| **디코더** | 인코더가 넘긴 임베딩 + **지금까지 자신이 만든 출력**을 함께 참조해 **다음 토큰 하나를 생성**. 출력이 하나씩 쌓이고, 쌓인 출력이 매번 다시 입력 (Das ist ein → Beispiel) |
| **층 (블록)** | 두 모듈 안에서 벡터가 갱신되는 처리 단위. 한 번 지날 때마다 **문맥이 더 반영된** 벡터가 됨. 이 층을 여럿 쌓아 모듈을 구성 |
| **셀프 어텐션** | 층마다 들어 있는 **핵심 장치**. 시퀀스의 **어느 단어를 얼마나 참조할지 스스로 계산** → 문장이 길어져도 앞쪽 맥락이 유지되는 근거 (4장에서 직접 구현) |

**셀프 어텐션 예시**

> *"그 서버는 요청을 처리하지 못했다. **그것**이 과부하 상태였기 때문이다."*

- '그것'의 지시 대상은 '과부하'를 본 뒤에야 확정된다.
- 모델은 문장 안 다른 단어와의 **관련도를 수치로 계산**해 '서버'에는 **높은 값**, '요청'에는 **낮은 값**을 부여하고,
- 그 값의 **비율만큼** 각 단어의 정보를 끌어와 '그것'의 벡터를 구성한다.

### 9.2 두 변종: BERT와 GPT ⭐

| 항목 | **BERT** | **GPT** |
|---|---|---|
| 사용 모듈 | **인코더** — 앞뒤를 **모두** 참조 | **디코더** — **앞만** 참조 |
| 훈련 작업 | **마스킹된 단어 예측** — 빈칸 채우기 | **다음 토큰 예측** — 한 번에 하나씩 생성 |
| 강점 | **텍스트 분류** — 감성 분석, 유해 콘텐츠 감지 | **텍스트 생성** — 번역, 요약, 작문 |
| 이름 | **B**idirectional (양방향) Encoder Representations from Transformers | **G**enerative **P**re-trained **T**ransformer (생성하도록 미리 훈련) |

```
BERT:  "나는 [MASK]에 갔다"   → 앞("나는")과 뒤("에 갔다")를 모두 보고 빈칸 채우기
GPT:   "나는 은행에"  → ???   → 앞만 보고 다음 토큰 예측 (뒤쪽은 아직 없음)
```

- **차이의 근원은 참조 방향**: 디코더는 생성 시점에 **뒤쪽이 아직 없으므로** 앞만 보고 이어 쓸 수밖에 없고, 인코더는 문장이 **이미 다 주어진 상태**에서 빈칸을 메우므로 앞뒤를 모두 볼 수 있다.

### 9.3 계보

```
트랜스포머(2017) ─▶ GPT ─▶ GPT-2 ─▶ GPT-3(2020) ─[지시 미세 튜닝: InstructGPT]─▶ ChatGPT 초기 모델
                                     구조는 같고 파라미터·데이터만 확장
```

- **GPT-3**는 구조를 새로 만든 것이 아니라 **파라미터 수와 데이터양을 함께 키운 확장판**
- **ChatGPT 초기 모델** = GPT-3 + **지시 미세 튜닝**. 그 방법을 정리한 논문이 **InstructGPT**

### 9.4 ⚠️ 트랜스포머 ≠ LLM

- 트랜스포머가 전부 LLM인 것은 **아니다** → **컴퓨터 비전**에도 쓰임
- LLM이 전부 트랜스포머인 것도 **아니다** → **순환·합성곱 신경망** 기반 LLM도 존재 (동기는 계산 효율이지만 아직 대체할 만큼 자리 잡지 못함)
- 이 강의에서 'LLM'은 **GPT 같은 트랜스포머 기반 모델**을 지칭

## 10. GPT의 구조와 규모

### 10.1 핵심 특징

| 특징 | 설명 |
|---|---|
| **디코더 전용** | 번역처럼 따로 읽을 원문이 있을 때만 인코더가 필요. GPT는 입력 텍스트와 생성 결과를 **하나의 시퀀스로 이어 붙여** 처리 → 인코더도, 인코더 출력을 참조하는 **크로스 어텐션도 불필요** |
| **자기회귀 (autoregressive)** | **자기가 만든 출력을 다시 자기 입력으로** 사용. 매 예측마다 지금까지 생성된 시퀀스 전체를 참조하므로 앞뒤가 어긋나지 않음 |
| **규모** | 원본 트랜스포머: 인코더·디코더 블록 **각 6개** / GPT-3: **디코더 블록만 96개**, 파라미터 **1,750억 개** |
| **블록 골격** | **셀프 어텐션 + 피드포워드**(벡터를 한 번 더 변환)는 같음. 차이는 크로스 어텐션 제거와 층 수·벡터 차원 확대 |
| **지금도 유효** | GPT-3는 2020년 모델이지만 **디코더 전용 구조·자기회귀 생성·다음 토큰 예측**은 최신 모델에도 그대로 유지 |

> ### 🧪 실습 C. 자기회귀 생성 = 한 번에 한 단어씩
>
> 실제 모델은 신경망이 **확률로** 다음 단어를 고르지만, 여기서는 이해를 돕기 위해 **미리 정해 둔 규칙표**를 쓴다.
>
> ```python
> next_word_rule = {
>     "This": "is",
>     "This is": "an",
>     "This is an": "example",
>     "This is an example": "<끝>",
> }
>
> generated = "This"
> for round_no in range(1, 5):
>     nxt = next_word_rule.get(generated, "<끝>")
>     if nxt == "<끝>":
>         print(f"{round_no}라운드: 종료 토큰 -> 생성 완료")
>         break
>     # 핵심: 이전 라운드의 출력이 다음 라운드의 입력이 된다 (자기회귀)
>     print(f"{round_no}라운드: 입력 {generated!r:<28} -> 다음 단어 {nxt!r}")
>     generated = generated + " " + nxt
> ```
>
> **실행 결과**
>
> ```
> 1라운드: 입력 'This'          -> 다음 단어 'is'
> 2라운드: 입력 'This is'       -> 다음 단어 'an'
> 3라운드: 입력 'This is an'    -> 다음 단어 'example'
> 4라운드: 종료 토큰 -> 생성 완료
> 최종 생성 결과: 'This is an example'
> ```
>
> 💡 핵심은 `generated = generated + " " + nxt` 한 줄이다. **출력이 다음 입력에 이어 붙는다** = 자기회귀. ChatGPT의 답이 글자가 하나씩 나타나는 것도 이 때문이다.

### 10.2 창발적 행동 (Emergent Behavior)

- 지도 학습이라면 번역용 데이터에 번역이라는 목표를 세워 훈련해야 하지만,
- GPT는 **다음 토큰 예측만으로** 번역·분류·요약을 수행한다.
- 여러 언어가 섞인 대용량 데이터를 학습한 결과이며, **작업별 개별 모델이 불필요해진 근거**다.

### 10.3 재훈련 없이 새 작업을 수행하는 세 방식 ⭐

| 방식 | 의미 | 입력 → 출력 예 |
|---|---|---|
| **텍스트 완성** | 훈련 과제 그대로 | `Breakfast is the most important` → `meal of the day.` |
| **제로-샷 (zero-shot)** | **예시 없이** 지시만으로 처음 보는 작업 수행 | `Translate English to German: breakfast =>` → `Frühstück` |
| **퓨-샷 (few-shot)** | **예시 몇 개**에서 규칙을 파악해 수행 | `gaot => goat`, `sheo => shoe`, `pohne =>` → `phone` |

- 세 경우 모두 **재훈련·미세 튜닝·구조 변경이 없다**. 모델 내부 값은 불변이고 달라진 것은 **입력 텍스트뿐**
- 이 사용법의 이름이 **프롬프트(prompt)**
- 사용자는 명령어나 메뉴가 아니라 **일상 문장**으로 요구를 전달 → **LLM의 자연어 인터페이스**

## 11. 데이터의 규모와 비용 — GPT-3 사전 훈련 데이터셋

| 데이터셋 | 설명 | 토큰 개수 | 훈련 비율 |
|---|---|---|---|
| **CommonCrawl** | 웹 전반을 긁어모은 뒤 걸러낸 데이터 | 4,100억 | 60% |
| **WebText2** | 선별된 웹 데이터 — **고품질** | 190억 | 22% |
| **Books1 · Books2** | 인터넷 기반 도서 데이터셋 | 120억 · 550억 | 8% · 8% |
| **위키백과** | 백과사전 문서 — **고품질** | 30억 | 3% |
| **합계** | 실제 훈련량은 **3,000억 토큰** | 4,990억 | 101%* |

**해석 포인트**
- 3,000억은 4,990억에서 골라낸 **부분집합이 아니라**, 소스별 **사용 횟수를 달리해 채운 배합**
  - WebText2·위키백과는 **세 번 가까이 반복** 사용
  - CommonCrawl은 **절반도 쓰지 않음**
- **토큰 양에 비례하지 않는 배합**: CommonCrawl은 WebText2보다 토큰이 **20배 넘게** 많지만 훈련 비율은 **3배 미만** → 고품질 소스를 더 자주 재사용. **데이터는 양뿐 아니라 품질 배합까지 설계 대상**
- (*비율 합계 101%는 GPT-3 논문 표기 그대로이며 반올림의 결과)

**[보충] 반복 횟수 계산해 보기** (훈련량 3,000억 × 비율 ÷ 원본 토큰 수)
- WebText2: 3,000억 × 0.22 ÷ 190억 ≈ **3.5회** — 원 논문에는 2.9회로 나오는데, 논문의 토큰 수와 반올림이 달라 차이가 생긴다.
- CommonCrawl: 3,000억 × 0.60 ÷ 4,100억 ≈ **0.44회**

**비용**
- 사전 훈련 비용: 클라우드 기준 약 **460만 달러** (원화 약 **60억 원**) 추정 → 개인이나 대부분의 조직이 감당할 규모가 아님
- 모델의 구성 요소는 **구조 + 가중치**
  - 구조만 구현한 상태의 가중치는 **무작위 값**이라 출력이 무의미
  - 그 값을 쓸 만하게 바꾸는 과정이 460만 달러짜리 사전 훈련
  - 같은 구조라면 **공개 모델의 가중치를 받아 넣어** 이 단계를 생략할 수 있음 (이 강의의 7단계)

---

## 12. 구현 3단계 로드맵

```
┌──────────── 1단계: LLM 만들기 ────────────┐  ┌──── 2단계: 파운데이션 모델 ────┐  ┌──── 3단계: 미세 튜닝 ────┐
│ ① 데이터 준비·샘플링   ← 2장·3장          │  │ ⑤ 훈련 반복                    │  │ ⑧ 분류기                  │
│ ② 어텐션 메커니즘      ← 4장~             │  │ ⑥ 모델 평가                    │  │   (클래스 레이블 데이터셋) │
│ ③ LLM 구조                                │  │ ⑦ 사전 훈련된 가중치 로드      │  │ ⑨ 대화형 모델             │
│ ④ 사전 훈련                               │  │                                │  │   (지시 데이터셋)          │
└───────────────────────────────────────────┘  └────────────────────────────────┘  └───────────────────────────┘
```

- ①~③으로 모델의 **형태**가 갖춰지나 가중치는 아직 **무작위 값**
- 그 자리를 채우는 작업이 ④ **사전 훈련**이고, 2단계 ⑤~⑦이 그 **실행 과정**
- **이 강의의 초점**: 서비스 사용법이나 프롬프트 작성법이 아니라 **LLM의 구성 요소를 직접 구현해 동작 원리를 이해**하는 것
- 다음 장은 **텍스트를 토큰으로 바꾸는 일**에서 시작한다.

## 13. 요약

- **LLM** = 대규모 텍스트로 훈련된 심층 신경망. **대규모 = 파라미터 수 + 데이터양**
- 훈련 과제는 **다음 토큰 예측** 하나. 이것만으로 문맥 이해와 번역·요약 같은 능력이 **창발**
- **토큰**: 모델이 읽는 단위이자 데이터양의 단위. GPT-2 어휘 사전 50,257개
- AI ⊃ 머신러닝 ⊃ 딥러닝 ⊃ LLM. **생성 AI와 LLM은 교차 관계**
- 딥러닝은 **특성 추출을 자동화**(레이블은 여전히 사람이)
- **사전 훈련**(레이블 없음, 다음 토큰 예측 → 파운데이션 모델) + **미세 튜닝**(레이블 있음, 지시 / 분류)
- **자기 지도 학습**: 다음 단어가 곧 정답 → 레이블이 공짜
- **트랜스포머** = 인코더 + 디코더, 핵심은 **셀프 어텐션**
- **BERT**(인코더, 양방향, 빈칸 채우기, 분류) vs **GPT**(디코더, 앞만, 다음 토큰, 생성)
- GPT = **디코더 전용 + 자기회귀**. GPT-3: 96블록, 1,750억 파라미터, 3,000억 토큰, 약 460만 달러
- 재훈련 없이: **텍스트 완성 / 제로-샷 / 퓨-샷** → 프롬프트

### 🧠 마인드맵

```
LLM 이해하기
├── 정의: 텍스트 이해·생성 심층 신경망
│   ├── 대규모 = 파라미터(GPT-3 1,750억) + 데이터
│   ├── 훈련 과제 = 다음 토큰 예측
│   └── 토큰 / 토크나이저 / 어휘 사전 (GPT-2: 50,257)
├── 위치: AI ⊃ ML ⊃ DL ⊃ LLM, 생성 AI와 교차
├── 전통 ML(특성 수동) vs DL(특성 자동) — 레이블은 둘 다 사람
├── 두 단계 훈련
│   ├── 사전 훈련: 원시 텍스트, 자기 지도 학습 → 파운데이션 모델
│   └── 미세 튜닝: 지시(ChatGPT) / 분류
├── 트랜스포머(2017)
│   ├── 인코더 + 디코더, 셀프 어텐션
│   ├── BERT: 인코더, 양방향, 마스킹 예측
│   └── GPT: 디코더, 단방향, 다음 토큰 예측
├── GPT: 디코더 전용, 자기회귀, 창발적 행동
│   └── 텍스트 완성 / 제로-샷 / 퓨-샷 (프롬프트)
└── 구현 로드맵: ①데이터 ②어텐션 ③구조 ④사전훈련 → ⑤~⑦ → ⑧분류 ⑨대화
```

## 14. 셀프 체크 퀴즈

**Q1.** '대규모' 언어 모델에서 '대규모'의 두 축은? 둘 중 하나만 크면 왜 안 되는가?

<details><summary>▶ 정답</summary>

파라미터의 수와 훈련 데이터의 양. 파라미터만 많으면 담을 지식이 없고, 데이터만 많으면 담을 용량이 부족하다. 둘이 함께 커져야 한다.
</details>

**Q2.** "다음 단어 예측"이라는 단순한 과제로 문맥을 이해하게 되는 이유를 예시로 설명하라.

<details><summary>▶ 정답</summary>

"나는 통장을 새로 만들려고 ___에 갔다"에서 '은행'을 맞히려면 '통장', '만들다'와의 의미 관계를 파악해야 한다. 다음 단어를 맞히는 일 자체가 문맥 파악을 요구한다.
</details>

**Q3.** `"LLMs"`가 GPT-2 토크나이저에서 두 토큰(`LL`, `Ms`)으로 나뉘는 이유는? 한글 문장이 토큰 수가 많은 이유는?

<details><summary>▶ 정답</summary>

흔하지 않은 표기라 어휘 사전에 통째로 등록되어 있지 않아 사전에 있는 조각으로 쪼개진다. 한글은 GPT-2 사전에 거의 없어 더 잘게(바이트 단위로) 쪼개진다.
</details>

**Q4.** 생성 AI와 LLM의 관계는 포함인가 교차인가? 예를 들어 설명하라.

<details><summary>▶ 정답</summary>

교차 관계. LLM이 글을 쓰는 작업은 생성 AI에 해당하지만, 스팸 판정처럼 고르기만 하는 작업은 생성이 아니다. 또 생성 AI에는 LLM이 아닌 이미지·오디오 생성도 포함된다.
</details>

**Q5.** 딥러닝이 전통적인 머신러닝에 비해 자동화한 것과 자동화하지 않은 것은?

<details><summary>▶ 정답</summary>

자동화한 것: 특성 추출. 자동화하지 않은 것: 레이블 수집 (여전히 사람이 한다).
</details>

**Q6.** 사전 훈련과 미세 튜닝을 데이터·학습 목표·결과로 비교하라.

<details><summary>▶ 정답</summary>

- 사전 훈련: 레이블 없는 대규모 원시 텍스트 / 다음 토큰 예측 / 파운데이션 모델
- 미세 튜닝: 레이블 있는 작은 데이터셋 / 지시 수행 또는 분류 / 작업에 맞춰진 LLM
</details>

**Q7.** 자기 지도 학습이 "레이블이 필요 없다"고 하는 이유는? 단어 6개짜리 문장에서 만들어지는 (입력, 정답) 쌍은 몇 개인가?

<details><summary>▶ 정답</summary>

텍스트의 각 위치에서 다음 단어가 곧 정답이므로 데이터 자체에서 레이블이 생긴다. 단어 6개면 5개 쌍 (실습 B처럼 n−1개).
</details>

**Q8.** BERT와 GPT를 사용 모듈·참조 방향·훈련 작업·강점으로 비교하라.

<details><summary>▶ 정답</summary>

- BERT: 인코더 / 앞뒤 모두(양방향) / 마스킹된 단어 예측 / 분류
- GPT: 디코더 / 앞만 / 다음 토큰 예측 / 생성
</details>

**Q9.** GPT에 인코더와 크로스 어텐션이 필요 없는 이유는?

<details><summary>▶ 정답</summary>

번역처럼 따로 읽을 원문이 없고, 입력 텍스트와 생성 결과를 하나의 시퀀스로 이어 붙여 디코더만으로 처리하기 때문이다.
</details>

**Q10.** "자기회귀"를 실습 C의 코드 한 줄로 설명하라.

<details><summary>▶ 정답</summary>

`generated = generated + " " + nxt` — 이번 라운드의 출력을 다음 라운드의 입력에 이어 붙인다.
</details>

**Q11.** 제로-샷과 퓨-샷의 차이는? 둘 다 공통으로 하지 않는 것은?

<details><summary>▶ 정답</summary>

제로-샷은 예시 없이 지시만, 퓨-샷은 예시 몇 개를 함께 준다. 둘 다 재훈련·미세 튜닝·구조 변경을 하지 않는다 (입력 텍스트만 바뀜).
</details>

**Q12.** GPT-3 데이터에서 CommonCrawl은 토큰이 가장 많은데 왜 훈련 비율은 토큰 양에 비례하지 않는가?

<details><summary>▶ 정답</summary>

품질이 높은 WebText2·위키백과를 여러 번 반복 사용하고, 품질이 낮은 CommonCrawl은 절반도 쓰지 않도록 배합을 설계했기 때문이다.
</details>

**Q13.** 맞춤형 LLM의 네 가지 장점은?

<details><summary>▶ 정답</summary>

데이터 개인정보 보호, 온디바이스 배포, 응답 시간과 비용 절감, 완전한 자율성
</details>

**Q14.** "트랜스포머 = LLM"이 틀린 이유 두 가지는?

<details><summary>▶ 정답</summary>

트랜스포머는 컴퓨터 비전 등에도 쓰이고, 순환·합성곱 신경망 기반 LLM도 존재한다.
</details>

### 📚 용어 사전

| 용어 | 정의 |
|---|---|
| LLM | 대규모 텍스트로 훈련된, 텍스트를 이해·생성하는 심층 신경망 |
| 파라미터 | 신경망의 가중치. 모델이 배운 것이 저장되는 곳 |
| 토큰 / 토큰 ID | 모델이 읽는 텍스트 단위 / 그 단위에 대응하는 정수 |
| 토크나이저 / 어휘 사전 | 텍스트를 토큰으로 나누는 도구 / 그 도구가 아는 토큰 목록 |
| 특성 / 레이블 | 판단에 쓰이는 숫자 값 / 데이터의 정답 표시 |
| 사전 훈련 | 원시 텍스트로 다음 토큰 예측을 학습하는 단계 |
| 파운데이션 모델 | 사전 훈련으로 얻은 베이스 모델 |
| 미세 튜닝 | 레이블 데이터로 특정 작업에 맞추는 단계 (지시 / 분류) |
| 자기 지도 학습 | 데이터 자체에서 레이블을 만들어 학습 |
| 트랜스포머 | 인코더·디코더와 셀프 어텐션으로 구성된 구조 (2017) |
| 셀프 어텐션 | 시퀀스 안 다른 토큰을 얼마나 참조할지 계산하는 장치 |
| 자기회귀 | 자신의 출력을 다시 입력으로 사용해 하나씩 생성 |
| 창발적 행동 | 명시적으로 훈련하지 않은 능력이 나타나는 현상 |
| 제로-샷 / 퓨-샷 | 예시 없이 / 예시 몇 개로 새 작업 수행 |
| 프롬프트 | 모델에 넣는 입력 텍스트 (자연어 인터페이스) |
