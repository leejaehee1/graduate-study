## 1. 다음 단어 예측과 입력·타깃 쌍

**전제**: LLM 사전 훈련 = 텍스트에서 **다음 단어를 예측**하는 작업 = 1장의 **자기 지도 학습**. 텍스트 안에 다음 단어가 이미 있으므로 레이블을 따로 만들 필요 없이 입력 데이터에서 그대로 얻는다.

| 개념 | 설명 |
|---|---|
| **입력과 타깃** | 텍스트 앞부분을 **입력**으로 주고, 바로 **다음 단어 하나**를 **타깃**으로 삼음 |
| **마스킹** | 타깃 뒤의 단어는 모델이 볼 수 없게 가린다. 답을 보고 맞히면 훈련이 되지 않기 때문. ⚠️ **데이터 로더가 가리는 것이 아니라**, 4–5장 어텐션의 **인과적(코잘) 마스크**가 이 역할을 한다 |
| **슬라이딩 윈도** | 한 줄에서 쌍을 하나만 뽑으면 데이터가 너무 적다. 추출 위치를 **한 단어씩 옮기면** 단어 수만큼 쌍이 나온다 |

```
텍스트:  The  cat  sat  on  the  mat
        ├────────────────┤
        │ 윈도 (크기 4)   │ → 다음 단어
```

| 위치 | 입력 (윈도) | 타깃 (다음 단어) |
|---|---|---|
| 1 | The cat sat on | **the** |
| 2 | cat sat on the | **mat** |
| 3 | sat on the mat | … |

- 문장 길이 $n$, 윈도 크기 $w$ → 약 $n - w$ 개의 쌍을 뽑을 수 있다.
- 도식은 이해를 돕기 위해 **단어** 단위로 그리지만, 실제 처리는 **토큰 ID** 단위다.

## 2. 입력 x와 타깃 y: 한 토큰 이동

> ### 🧪 실습: 소설 전체를 BPE로 토큰화
>
> ```python
> import tiktoken
> tokenizer = tiktoken.get_encoding("gpt2")
> with open("the-verdict.txt", "r", encoding="utf-8") as f:
>     raw_text = f.read()
>
> enc_text = tokenizer.encode(raw_text)
> print(len(enc_text))   # 5145
> ```
>
> 💡 2장의 정규식 토크나이저는 **4,690**개였는데 BPE는 **5,145**개다. BPE가 흔하지 않은 단어를 부분단어로 쪼개고 공백도 토큰에 포함하기 때문이다.

| 용어 | 의미 |
|---|---|
| **슬라이싱** | 목록에서 일부 구간을 지정하는 것. `lst[a:b]` |
| **컨텍스트 사이즈** | 입력에 포함하는 토큰 수 (예시에서는 4) |

> ### 🧪 실습: x와 y 만들기
>
> ```python
> enc_sample = enc_text[50:]     # 앞 50개는 설명 편의상 건너뜀
>
> context_size = 4
> x = enc_sample[:context_size]           # 0~3번
> y = enc_sample[1:context_size + 1]      # 1~4번 (한 칸 오른쪽)
> print(f"x: {x}")
> print(f"y:      {y}")
> ```
>
> ```
> x: [290, 4920, 2241, 287]
> y:      [4920, 2241, 287, 257]
> ```

**한 토큰 이동의 의미** ⭐

```
위치:     0      1      2      3
x:     [ 290, 4920, 2241,  287 ]
          ↘     ↘     ↘     ↘
y:     [4920, 2241,  287,  257 ]
```

- $y$를 $x$보다 **한 토큰 뒤**에서 시작 → $x$의 뒤쪽 세 값 = $y$의 앞쪽 세 값
- $x$의 **어느 위치든 그다음 토큰**이 $y$의 **같은 위치**에 있다.
- → 모델이 $y$를 맞히는 것 = 각 위치에서 **다음 토큰을 예측**하는 것

> ### 🧪 실습: 예측 쌍 확인
>
> ```python
> for i in range(1, context_size + 1):
>     context = enc_sample[:i]
>     desired = enc_sample[i]
>     print(tokenizer.decode(context), "---->", tokenizer.decode([desired]))
> ```
>
> | 토큰 ID 입력 | → 타깃 | 글자로 보면 |
> |---|---|---|
> | `[290]` | 4920 | ` and` → ` established` |
> | `[290, 4920]` | 2241 | ` and established` → ` himself` |
> | `[290, 4920, 2241]` | 287 | ` and established himself` → ` in` |
> | `[290, 4920, 2241, 287]` | 257 | ` and established himself in` → ` a` |
>
> → 입력 **4토큰짜리 한 쌍(x, y)** 안에 **예측 문제가 4개** 들어 있다 (컨텍스트 사이즈만큼). 실제 훈련에는 글자가 아니라 **토큰 ID**를 쓴다.

## 3. 배치 텐서와 GPTDatasetV1

| 용어 | 의미 |
|---|---|
| **텐서** | 파이토치가 계산에 쓰는 **다차원 배열**. 모델은 이 형태로만 데이터를 받음 |
| **데이터 로더** | 텍스트를 받아 입력과 타깃을 **텐서로 반환**하는 장치 |
| **행** | 텐서 x의 한 행 = 입력 하나. 텐서 y의 **같은 행**에 그 입력의 타깃 |
| **배치** | 여러 입력·타깃을 **행으로 쌓아 한 번에 처리**하는 단위 |

```
       입력 텐서 x                    타깃 텐서 y
행 0: [ 40,  367, 2885, 1464]   ↔   [ 367, 2885, 1464, 1807]
행 1: [1807, 3619,  402,  271]   ↔   [3619,  402,  271, 10899]
 ⋮              ⋮                              ⋮
         └── 행 번호로 짝을 맞춘다 ──┘
```

**GPTDatasetV1 구성 요소**

| 메서드 | 역할 | 세부 |
|---|---|---|
| `__init__` | **슬라이딩 윈도 적용** | 텍스트를 인코드 → 윈도 크기 `max_length`, 이동 폭 `stride`로 입력·타깃을 잘라 각각 텐서로 저장 |
| `__len__` | **행 수** 반환 | 저장된 입력·타깃 쌍의 총 개수 |
| `__getitem__` | **한 행** 반환 | 행 번호를 받아 그 행의 (입력, 타깃) 한 쌍 반환 |

> ### 🧪 실습: GPTDatasetV1
>
> ```python
> import torch
> from torch.utils.data import Dataset, DataLoader
>
> class GPTDatasetV1(Dataset):
>     def __init__(self, txt, tokenizer, max_length, stride):
>         self.input_ids = []
>         self.target_ids = []
>         token_ids = tokenizer.encode(txt)                        # 텍스트 전체 → 토큰 ID
>         for i in range(0, len(token_ids) - max_length, stride):  # stride만큼 윈도 이동
>             input_chunk = token_ids[i:i + max_length]            # 입력
>             target_chunk = token_ids[i + 1: i + max_length + 1]  # 타깃 = 한 칸 오른쪽
>             self.input_ids.append(torch.tensor(input_chunk))
>             self.target_ids.append(torch.tensor(target_chunk))
>
>     def __len__(self):
>         return len(self.input_ids)
>
>     def __getitem__(self, idx):
>         return self.input_ids[idx], self.target_ids[idx]
> ```
>
> **코드 읽기 포인트**
> - `range(0, len(token_ids) - max_length, stride)`: 마지막 윈도의 **타깃**이 텍스트 밖으로 나가지 않도록 `- max_length`
> - `target_chunk`가 `input_chunk`보다 **1씩 밀린** 것 = 2절의 한 토큰 이동

- **역할 분담**: `__len__`과 `__getitem__`으로 **한 행씩 추출**하는 것까지가 **데이터셋**의 역할, 그 행들을 **배치 텐서로 묶는 것**은 **데이터 로더**가 담당한다.

## 4. create_dataloader_v1: 배치 생성

> ### 🧪 실습
>
> ```python
> def create_dataloader_v1(txt, batch_size=4, max_length=256,
>                          stride=128, shuffle=True, drop_last=True,
>                          num_workers=0):
>     tokenizer = tiktoken.get_encoding("gpt2")
>     dataset = GPTDatasetV1(txt, tokenizer, max_length, stride)
>     dataloader = DataLoader(
>         dataset, batch_size=batch_size, shuffle=shuffle,
>         drop_last=drop_last, num_workers=num_workers)
>     return dataloader
> ```

| 매개변수 | 전달 대상 | 역할 |
|---|---|---|
| `max_length` | 데이터셋 | **윈도 크기** (한 행의 토큰 수) |
| `stride` | 데이터셋 | **이동 폭** (다음 행이 몇 토큰 뒤에서 시작하는지) |
| `batch_size` | 데이터 로더 | 한 배치에 **몇 행**을 담을지 |
| `shuffle` | 데이터 로더 | 참이면 행 순서를 **무작위로 섞음** |
| `drop_last` | 데이터 로더 | 참이면 행 수 ÷ 배치 크기의 **나머지로 생긴 마지막 배치를 삭제**. 크기가 다른 배치가 섞이면 그 배치에서 **훈련 손실이 급등**하기 때문 |
| `num_workers` | 데이터 로더 | 전처리에 쓸 **CPU 프로세스 수** |

**[보충] 몇 행, 몇 배치가 나올까?** (소설 5,145토큰 기준, 행 수 = `len(range(0, 5145 - max_length, stride))`)

| max_length | stride | 행 수 | batch_size=8, drop_last 배치 수 |
|---|---|---|---|
| 4 | 1 | 5,141 | 642 |
| 4 | 4 | 1,286 | 160 |
| 256 | 128 | 39 | 4 |

## 5. 데이터 로더 테스트: 연속 배치와 스트라이드

> ### 🧪 실습: stride=1 로 연속 두 배치 보기
>
> ```python
> dataloader = create_dataloader_v1(
>     raw_text, batch_size=1, max_length=4, stride=1, shuffle=False)
> data_iter = iter(dataloader)
> print(next(data_iter))
> print(next(data_iter))
> ```
>
> ```
> [tensor([[  40,  367, 2885, 1464]]), tensor([[ 367, 2885, 1464, 1807]])]   ← 배치 1: (입력, 타깃)
> [tensor([[ 367, 2885, 1464, 1807]]), tensor([[2885, 1464, 1807, 3619]])]   ← 배치 2: (입력, 타깃)
> ```

- **첫 배치의 타깃 = 둘째 배치의 입력** (`[367, 2885, 1464, 1807]`)
- 값은 같지만 **두 이동의 목적은 다르다** ⭐
  - 타깃 이동: **다음 토큰을 정답으로** 지정하려는 것 (항상 1)
  - 둘째 입력 이동: **stride가 1**이라서 생긴 것 (stride를 바꾸면 달라짐)

### 스트라이드가 배치 구성에 미치는 영향

> ### 🧪 실습: 스트라이드 실험 (연습문제 2.2)
>
> ```python
> for ml, st in [(2, 2), (8, 2), (4, 4)]:
>     dl = create_dataloader_v1(raw_text, batch_size=1, max_length=ml, stride=st, shuffle=False)
>     it = iter(dl)
>     b1 = next(it)[0]
>     b2 = next(it)[0]
>     print(f"max_length={ml}, stride={st}")
>     print("  배치1 입력:", b1.tolist())
>     print("  배치2 입력:", b2.tolist())
> ```
>
> | max_length | stride | 배치1 입력 | 배치2 입력 | 겹침 |
> |---|---|---|---|---|
> | 2 | 2 | `[40, 367]` | `[2885, 1464]` | 없음 |
> | 8 | 2 | `[40, 367, 2885, 1464, 1807, 3619, 402, 271]` | `[2885, 1464, 1807, 3619, 402, 271, 10899, 2138]` | **6토큰** 겹침 |
> | 4 | 4 | `[40, 367, 2885, 1464]` | `[1807, 3619, 402, 271]` | 없음 |

```
토큰:   40  367 2885 1464 1807 3619  402  271 ...

stride=1 (max_length=4)
배치1: [40  367 2885 1464]
배치2:     [367 2885 1464 1807]          → 3토큰 겹침

stride=4 (max_length=4)
배치1: [40  367 2885 1464]
배치2:                     [1807 3619  402  271]   → 겹침 없음, 빠짐 없음

stride=6 (max_length=4)  [보충]
배치1: [40  367 2885 1464]
배치2:                              [402  271 ...]   → 1807, 3619는 어느 배치에도 안 들어감!
```

| 경우 | 효과 |
|---|---|
| **stride < max_length** | 배치끼리 토큰이 **겹침** → 같은 데이터를 여러 번 봄 |
| **stride = max_length** ⭐ | 겹침 없음 → **과대적합(overfitting)을 줄임**. 건너뛰는 토큰도 없어 **데이터를 빠짐없이 활용** |
| **stride > max_length** | 그 사이 토큰은 **어느 배치에도 들어가지 않음** |

**배치 크기와 하이퍼파라미터**
- 배치가 **작으면** 메모리는 덜 쓰지만 모델 업데이트 방향에 **잡음이 늘어남**
- 배치 크기는 훈련할 때 **실험으로 정하는 하이퍼파라미터**다.

## 6. 토큰 ID를 벡터로: 임베딩의 필요성

```
2장: 텍스트 → 토큰 → 토큰 ID      3장 후반: 토큰 ID → 임베딩 벡터      4장~: 모델이 처리
```

| 질문 | 답 |
|---|---|
| **왜 벡터가 필요한가?** | 모델은 **실수 벡터로 연산**하는데, 토큰 ID는 어휘사전의 **인덱스일 뿐** 그 자체로 의미가 없다 (ID 2와 ID 3이 "가깝다"는 뜻이 아님). 그래서 토큰 하나에 **실수 벡터 하나**를 대응시킨다 = 임베딩 |
| **값은 어떻게 정하나?** | 처음에는 **작은 랜덤 값**으로 초기화하고, 모델 훈련 동안 **다른 가중치와 함께 최적화**된다 |

## 7. 임베딩 층 = 룩업 연산

> ### 🧪 실습: 어휘 6개 × 3차원 미니어처
>
> ```python
> input_ids = torch.tensor([2, 3, 5, 1])
> vocab_size = 6
> output_dim = 3
>
> torch.manual_seed(123)
> embedding_layer = torch.nn.Embedding(vocab_size, output_dim)
> print(embedding_layer.weight)   # 6행 3열 가중치 행렬
> ```
>
> ```
> Parameter containing:
> tensor([[ 0.3374, -0.1778, -0.1690],    ← 행 0 (토큰 ID 0)
>         [ 0.9178,  1.5810,  1.3010],    ← 행 1 (토큰 ID 1)
>         [ 1.2753, -0.2010, -0.1606],    ← 행 2
>         [-0.4015,  0.9666, -1.1481],    ← 행 3
>         [-1.1589,  0.3255, -0.6315],    ← 행 4
>         [-2.8400, -0.7849, -1.4096]],   ← 행 5
>        requires_grad=True)
> ```

**가중치 행렬**

| 차원 | 의미 |
|---|---|
| **행 수 = 6** | 어휘사전 크기 (토큰 종류 수). 행 하나 = 토큰 하나의 벡터 |
| **열 수 = 3** | 임베딩 차원 |
| **행 번호** | = **토큰 ID** |

- `requires_grad=True` → 훈련으로 **조정되는 가중치**이므로 "가중치 행렬"

> ### 🧪 실습: 룩업
>
> ```python
> print(embedding_layer(torch.tensor([3])))
> # tensor([[-0.4015,  0.9666, -1.1481]])   ← 가중치 행렬의 네 번째 행(인덱스 3)과 동일!
>
> print(embedding_layer(input_ids))          # 배치 룩업: ID [2, 3, 5, 1]
> # tensor([[ 1.2753, -0.2010, -0.1606],     ← 행 2
> #         [-0.4015,  0.9666, -1.1481],     ← 행 3
> #         [-2.8400, -0.7849, -1.4096],     ← 행 5
> #         [ 0.9178,  1.5810,  1.3010]])    ← 행 1
> ```

```
       가중치 행렬 (6 × 3)                  입력 ID [2, 3, 5, 1]
  0 │ 0.3374 -0.1778 -0.1690│                    │
  1 │ 0.9178  1.5810  1.3010│ ◀──────── ④ ───────┤
  2 │ 1.2753 -0.2010 -0.1606│ ◀──────── ① ───────┤
  3 │-0.4015  0.9666 -1.1481│ ◀──────── ② ───────┤
  4 │-1.1589  0.3255 -0.6315│                    │
  5 │-2.8400 -0.7849 -1.4096│ ◀──────── ③ ───────┘
                              → 결과: 4 × 3 (넘긴 순서대로)
```

**핵심 정리** ⭐
- 임베딩 층은 생성할 때 만든 가중치 행렬을 갖고 있다가, 토큰 ID를 받으면 **그 번호의 행을 읽어 반환**할 뿐이다.
- 출력의 **행 수 = 넘긴 토큰 수** (어휘사전 크기가 아님)
- 임베딩 층이 하는 일은 **곱셈이나 덧셈이 아니라, 번호로 행을 찾아 반환**하는 것뿐 = **룩업(lookup)**
- 실제 규모: GPT-2 어휘사전 **50,257**개, GPT-3 벡터 **12,288**차원

---

## 8. 원-핫 인코딩과의 관계

**원-핫 벡터**: 어휘사전 크기만큼 긴 벡터에서 토큰 ID 자리만 1, 나머지는 0

$$
\underbrace{[0,\;0,\;0,\;1,\;0,\;0]}_{\text{토큰 ID 3의 원-핫 (길이 6)}}
\times
\underbrace{\begin{bmatrix}
0.3374 & -0.1778 & -0.1690 \\
0.9178 & 1.5810 & 1.3010 \\
1.2753 & -0.2010 & -0.1606 \\
\mathbf{-0.4015} & \mathbf{0.9666} & \mathbf{-1.1481} \\
-1.1589 & 0.3255 & -0.6315 \\
-2.8400 & -0.7849 & -1.4096
\end{bmatrix}}_{W\ (6\times3)}
= [-0.4015,\; 0.9666,\; -1.1481]
$$

- 1인 자리의 행만 남고 0인 자리의 행은 사라진다 → **룩업과 같은 결과**

| 비교 | 내용 |
|---|---|
| **룩업이 더 효율적인 이유** | 어휘사전이 5만 개면 원-핫 벡터에 0이 거의 5만 개. 그 0을 전부 곱하는 연산은 결과에 기여하지 않는 **낭비**. 번호로 행을 바로 찾는 룩업이 같은 결과를 더 효율적으로 냄 |
| **임베딩 층이 훈련되는 이유** | 룩업이 행렬 곱셈과 **같은 결과**를 내므로, 행렬 곱셈처럼 **역전파로 가중치 행렬을 갱신**할 수 있다. 겉보기엔 행을 찾기만 하는 층이 훈련으로 값이 바뀌는 것은 이 때문 |

> ### 🧪 [보충] 실습: 원-핫 × 가중치 = 룩업 확인
>
> 노트북의 `embedding_layer`를 그대로 이어서 실행하면 된다.
>
> ```python
> import torch.nn.functional as F
>
> one_hot = F.one_hot(torch.tensor([3]), num_classes=6).float()   # [[0,0,0,1,0,0]]
> print(one_hot @ embedding_layer.weight)       # 행렬 곱
> print(embedding_layer(torch.tensor([3])))     # 룩업
> # 두 결과 모두 [[-0.4015, 0.9666, -1.1481]]
> ```

## 9. 토큰 임베딩의 한계: 위치 정보 부재

- 룩업은 입력의 **순번을 보지 않고** 토큰 ID로만 행을 찾는다.
- 같은 토큰 ID가 서로 다른 자리에 나오면 **같은 행 하나**를 가리키고, 출력만 받아서는 **어느 것이 앞이었는지 알 수 없다**.

```
"개가 사람을 물었다"  vs  "사람이 개를 물었다"
 → 토큰 임베딩만 보면 같은 단어들의 같은 벡터 → 순서 구분 불가
```

| 성질 | 평가 |
|---|---|
| 같은 토큰 ID → 항상 같은 벡터 | 👍 같은 입력에 같은 출력을 보장하는 좋은 특징 |
| 순서 정보가 없음 | 👎 같은 단어라도 순서가 다르면 뜻이 달라지는데 모델이 순서를 모름 |

- **어텐션에도 토큰 위치·순서 개념이 따로 없다** (4장) → 토큰 임베딩에 **위치 정보를 별도로 더해** 줘야 한다.

---

## 10. 절대 위치 임베딩 vs 상대 위치 임베딩

둘 다 모델이 **토큰 순서와 관계**를 알게 하려는 목적이며, 어느 쪽이 나은지는 정해져 있지 않고 **애플리케이션과 데이터의 성질**에 따라 선택한다.

| 방식 | 기준 | 장점 | 단점 |
|---|---|---|---|
| **절대 위치 임베딩** | **몇 번째인지** — 순번마다(첫째, 둘째, …) 고유한 벡터 | 토큰 임베딩과 차원이 같아 **그대로 더할** 수 있음. 같은 토큰이라도 순번이 다르면 결과가 달라짐 | **훈련 때 없던 순번**은 대응하는 벡터가 없음 |
| **상대 위치 임베딩** | **얼마나 떨어져 있는지** — 두 토큰 사이 거리 | 거리만 쓰므로 입력이 길어져도 관계 유지 → **훈련 데이터보다 긴 입력**에도 적용 가능 | – |

```
절대: "나는(0번) 밥을(1번) 먹었다(2번)"   → 0번 벡터, 1번 벡터, 2번 벡터를 각각 더함
상대: "나는 ↔ 밥을: 거리 1", "나는 ↔ 먹었다: 거리 2"   → 거리 정보를 사용
```

**GPT의 선택** ⭐
- 오픈AI의 GPT 계열은 **절대 위치 임베딩**을 사용
- 순번마다 벡터가 하나씩 있는 것은 같지만, 벡터 값을 **미리 정하지 않고** 토큰 임베딩처럼 **랜덤 값에서 시작해 훈련 과정에서 함께 최적화**한다 (학습되는 위치 임베딩).

---

## 11. 위치 임베딩 더하기: 입력 임베딩

$$
\text{입력 임베딩} = \text{토큰 임베딩} + \text{위치 임베딩}
$$

- 위치 임베딩은 토큰 임베딩과 **차원이 같아야** 더할 수 있다.
- 토큰 임베딩 값이 모두 같아도 **순번이 다르면** 위치 임베딩이 달라 **입력 임베딩도 달라진다**.
- 이 **단순 덧셈**으로 결합한 것이 모델에 들어가는 **최종 입력 임베딩**이다.

## 12. 현실적인 규모로 확인

```
[1단계] 토큰 임베딩 층           [2단계] 배치 추출                     [3단계] 위치 임베딩 층
어휘사전 50,257 (GPT-2 실제값)   batch_size=8, max_length=4            context_length=4 (순번 0~3)
차원 256 (실습용)                stride=4 → 배치 간 중첩 없음          차원 256 → 순번 0~3 룩업
```

> ### 🧪 실습: 토큰 임베딩 (8 × 4 × 256)
>
> ```python
> vocab_size = 50257
> output_dim = 256
> token_embedding_layer = torch.nn.Embedding(vocab_size, output_dim)
>
> max_length = 4
> dataloader = create_dataloader_v1(
>     raw_text, batch_size=8, max_length=max_length,
>     stride=max_length, shuffle=False)
> inputs, targets = next(iter(dataloader))
> print("토큰 ID:\n", inputs)
> print("입력 크기:", inputs.shape)               # torch.Size([8, 4])
>
> token_embeddings = token_embedding_layer(inputs)
> print("토큰 임베딩 크기:", token_embeddings.shape)   # torch.Size([8, 4, 256])
> ```
>
> ```
> 토큰 ID:
>  tensor([[   40,   367,  2885,  1464],
>          [ 1807,  3619,   402,   271],
>          [10899,  2138,   257,  7026],
>          [15632,   438,  2016,   257],
>          [  922,  5891,  1576,   438],
>          [  568,   340,   373,   645],
>          [ 1049,  5975,   284,   502],
>          [  284,  3285,   326,    11]])
> ```
>
> - 각 행이 **4토큰씩 겹침 없이** 이어진다 (stride = max_length)
> - 토큰 ID 하나하나가 **256개 값의 벡터**로 바뀌므로 `[8, 4]` → `[8, 4, 256]`

> ### 🧪 실습: 위치 임베딩 + 입력 임베딩
>
> ```python
> context_length = max_length                    # 4
> pos_embedding_layer = torch.nn.Embedding(context_length, output_dim)
> pos_embeddings = pos_embedding_layer(torch.arange(context_length))   # 순번 [0, 1, 2, 3] 룩업
> print("위치 임베딩 크기:", pos_embeddings.shape)      # torch.Size([4, 256])
>
> input_embeddings = token_embeddings + pos_embeddings
> print("입력 임베딩 크기:", input_embeddings.shape)    # torch.Size([8, 4, 256])
> ```
>
> - `torch.arange(4)` = `tensor([0, 1, 2, 3])` → 위치 임베딩 층에서 **순번 0~3의 행**을 룩업
> - 위치 임베딩 층은 토큰 임베딩 층과 **같은 구조**(`nn.Embedding`)지만, 행이 **토큰 종류가 아니라 순번**이다.

### 브로드캐스팅 ⭐

```
token_embeddings  [8, 4, 256]
pos_embeddings       [4, 256]   → 자동으로 [1, 4, 256] → 8개 행에 복사된 것처럼 동작
─────────────────────────────
input_embeddings  [8, 4, 256]
```

- 위치 임베딩(4 × 256)과 토큰 임베딩(8 × 4 × 256)은 크기가 다르다.
- 그런데 배치 안의 행 8개가 **모두 순번 0부터 3**이므로, 파이토치가 **같은 위치 임베딩을 행마다 더한다**.
- 이렇게 크기가 다른 텐서를 맞춰 더하는 것이 **브로드캐스팅**이다.
- 결과는 크기가 변하지 않은 **8 × 4 × 256**이며, 각 벡터에 **위치 정보만 더해진** 것이다.
- 실제 입력이 `context_length`보다 길면 순번 벡터가 없는 뒷부분은 **절단**된다.

> 🎯 `input_embeddings` (8 × 4 × 256) 이 이 장의 학습 목표였던, **모델에 들어가는 최종 입력**이다.

## 13. 텍스트에서 입력 임베딩까지: 전체 흐름

```
① 텍스트 ──[BPE 토크나이저 encode]──▶ ② 토큰 ID 한 줄 (5,145개 정수)
                                              │
                           [데이터 로더: max_length씩 끊어 행으로, batch_size만큼 묶음]
                                              ▼
                                   ③ 토큰 ID 배치 [8, 4]
                                     (행 = 배치 안 순서, 열 = 행 안 순번)
                                              │
                           [토큰 임베딩 층: 행 번호 = 토큰 ID로 룩업]
                                              ▼
                                   ④ 토큰 임베딩 [8, 4, 256]
                                              │
                ⑤ 위치 임베딩 층: 순번 0~3 룩업 → [4, 256] ──(+ 브로드캐스팅)
                                              ▼
                                   ⑥ 입력 임베딩 [8, 4, 256] ──▶ 4장 어텐션으로
```

| 단계 | 텐서 모양 | 하는 일 |
|---|---|---|
| 텍스트 → 토큰 ID | `[5145]` | BPE 인코드 |
| 토큰 ID → 배치 | `[8, 4]` | 슬라이딩 윈도 + 배치 묶기 |
| 배치 → 토큰 임베딩 | `[8, 4, 256]` | 룩업 (가중치 행렬 50,257 × 256) |
| 위치 임베딩 | `[4, 256]` | 순번 룩업 (가중치 행렬 4 × 256) |
| 입력 임베딩 | `[8, 4, 256]` | 덧셈 (브로드캐스팅) |

## 14. 요약

- LLM 사전 훈련 = 다음 단어 예측 → **슬라이딩 윈도**로 입력·타깃 쌍 생성
- **타깃 y = 입력 x를 한 토큰 오른쪽으로 민 것** → x의 각 위치에서 다음 토큰 예측
- **GPTDatasetV1**(`__init__`, `__len__`, `__getitem__`)이 행을 만들고, **DataLoader**가 배치로 묶음
- `max_length`(윈도 크기), `stride`(이동 폭), `batch_size`, `shuffle`, `drop_last`(손실 급등 방지)
- **stride = max_length** → 겹침·누락 없음, 과대적합 감소
- **임베딩 층 = 룩업**: 토큰 ID 번호의 행을 가중치 행렬에서 꺼냄
- 룩업 = **원-핫 × 가중치 행렬**과 같은 결과 → 역전파로 훈련 가능, 룩업이 더 효율적
- 토큰 임베딩에는 **순서 정보가 없음** → **위치 임베딩**을 더함
- **절대**(순번별 벡터, GPT 채택·학습됨) vs **상대**(토큰 간 거리, 긴 입력에 유리)
- **입력 임베딩 = 토큰 임베딩 + 위치 임베딩** (브로드캐스팅), 최종 `[8, 4, 256]`

### 🧠 마인드맵

```
데이터 샘플링과 임베딩
├── 입력·타깃 쌍
│   ├── 다음 단어 예측 (자기 지도 학습)
│   ├── 슬라이딩 윈도: n - w 개 쌍
│   └── y = x를 한 토큰 이동 → 위치마다 예측 문제
├── 데이터 로더
│   ├── GPTDatasetV1: __init__(윈도) / __len__ / __getitem__
│   ├── create_dataloader_v1: batch_size, max_length, stride, shuffle, drop_last
│   └── stride = max_length → 겹침·누락 없음
├── 토큰 임베딩
│   ├── nn.Embedding(vocab_size, dim) = 가중치 행렬
│   ├── 룩업: ID번째 행 반환
│   └── = 원-핫 × W (역전파 가능, 룩업이 효율적)
├── 위치 임베딩
│   ├── 필요성: 룩업·어텐션에 순서 개념 없음
│   ├── 절대(GPT, 학습됨) vs 상대(거리)
│   └── nn.Embedding(context_length, dim), torch.arange
└── 입력 임베딩 = 토큰 + 위치 (브로드캐스팅) → [8, 4, 256]
```

**Q4.** GPTDatasetV1의 `range(0, len(token_ids) - max_length, stride)`에서 `- max_length`가 필요한 이유는?

<details><summary>▶ 정답</summary>

타깃 청크가 `i+1`부터 `i+max_length+1`까지이므로, 마지막 윈도의 타깃이 텍스트 범위를 벗어나지 않게 하기 위해서다.
</details>

**Q5.** 데이터셋과 데이터 로더의 역할 분담은?

<details><summary>▶ 정답</summary>

데이터셋은 `__len__`과 `__getitem__`으로 한 행씩 (입력, 타깃)을 제공하고, 데이터 로더는 그 행들을 배치 텐서로 묶는다 (섞기, 마지막 배치 삭제 등 포함).
</details>

**Q6.** `drop_last=True`를 쓰는 이유는?

<details><summary>▶ 정답</summary>

행 수가 배치 크기로 나누어 떨어지지 않으면 마지막 배치 크기가 달라지는데, 그런 배치에서 훈련 손실이 급등할 수 있어 버린다.
</details>

**Q7.** stride=1일 때 첫 배치의 타깃과 둘째 배치의 입력이 같은 이유와, 두 "이동"의 목적 차이는?

<details><summary>▶ 정답</summary>

둘 다 첫 입력에서 한 토큰 뒤로 옮긴 것이라 값이 같다. 타깃 이동은 다음 토큰을 정답으로 지정하기 위한 것이고, 둘째 입력 이동은 stride가 1이라서 생긴 것이다.
</details>

**Q8.** max_length=4일 때 stride를 2, 4, 6으로 하면 각각 어떻게 되는가?

<details><summary>▶ 정답</summary>

- 2: 배치끼리 2토큰 겹침
- 4: 겹침도 누락도 없음 (과대적합 감소, 데이터 완전 활용)
- 6: 배치 사이 2토큰이 어느 배치에도 들어가지 않음
</details>

**Q9.** `nn.Embedding(6, 3)`의 가중치 행렬 모양은? `embedding_layer(torch.tensor([5, 0]))`의 결과 모양과 내용은?

<details><summary>▶ 정답</summary>

6 × 3. 결과는 2 × 3이며, 가중치 행렬의 5번 행과 0번 행을 순서대로 쌓은 것이다.
</details>

**Q10.** 임베딩 룩업과 원-핫 행렬 곱이 같은 결과를 내는 이유와, 룩업을 쓰는 이유는?

<details><summary>▶ 정답</summary>

원-핫 벡터는 해당 ID 자리만 1이라 곱하면 그 행만 남는다. 룩업은 0을 곱하는 불필요한 연산 없이 바로 행을 꺼내므로 훨씬 효율적이다.
</details>

**Q11.** 겉보기엔 행을 찾기만 하는 임베딩 층이 어떻게 훈련될 수 있는가?

<details><summary>▶ 정답</summary>

룩업이 원-핫 × 가중치 행렬이라는 행렬 곱셈과 같은 결과를 내므로, 행렬 곱셈처럼 역전파로 가중치 행렬을 갱신할 수 있다.
</details>

**Q12.** 위치 임베딩이 필요한 이유는?

<details><summary>▶ 정답</summary>

토큰 임베딩(룩업)은 순번을 보지 않아 같은 토큰은 위치와 관계없이 같은 벡터가 되고, 어텐션에도 순서 개념이 없다. 그래서 순서 정보를 따로 더해야 한다.
</details>

**Q13.** 절대 위치 임베딩과 상대 위치 임베딩의 차이와, GPT의 선택은?

<details><summary>▶ 정답</summary>

절대는 순번마다 고유 벡터(훈련 때 없던 순번은 벡터 없음), 상대는 토큰 간 거리 기준(긴 입력에도 적용 가능). GPT는 절대 위치 임베딩을 쓰되 값을 학습한다.
</details>

**Q14.** 토큰 임베딩 `[8, 4, 256]` + 위치 임베딩 `[4, 256]`의 결과 모양과, 이 덧셈이 가능한 원리는?

<details><summary>▶ 정답</summary>

`[8, 4, 256]`. 브로드캐스팅 — 위치 임베딩이 배치의 8개 행 모두에 똑같이 더해진다.
</details>

**Q15.** BPE로 토큰화한 소설 5,145토큰으로 `max_length=4, stride=4, batch_size=8, drop_last=True` 데이터 로더를 만들면 배치는 몇 개인가?

<details><summary>▶ 정답</summary>

행 수 = len(range(0, 5141, 4)) = 1,286 → 1,286 ÷ 8 = 160 (나머지 6행 버림) → **160개**
</details>

### 📚 용어 사전

| 용어 | 정의 |
|---|---|
| 슬라이딩 윈도 | 위치를 옮겨 가며 입력·타깃 쌍을 뽑는 방식 |
| 컨텍스트 사이즈 / max_length | 입력 한 행의 토큰 수 |
| stride | 윈도가 한 번에 이동하는 토큰 수 |
| 텐서 | 파이토치의 다차원 배열 |
| 배치 | 여러 행을 묶어 한 번에 처리하는 단위 |
| Dataset / DataLoader | 행 제공 / 배치 묶기를 담당하는 파이토치 클래스 |
| 하이퍼파라미터 | 사람이 실험으로 정하는 설정값 (배치 크기 등) |
| 임베딩 층 | 토큰 ID로 가중치 행렬의 행을 꺼내는 층 (`nn.Embedding`) |
| 룩업 | 번호로 행을 찾아 반환하는 연산 |
| 원-핫 벡터 | 한 자리만 1이고 나머지는 0인 벡터 |
| 역전파 | 오차를 거꾸로 전파해 가중치를 갱신하는 방법 |
| 절대 / 상대 위치 임베딩 | 순번 기준 / 거리 기준 위치 정보 |
| 입력 임베딩 | 토큰 임베딩 + 위치 임베딩, 모델의 최종 입력 |
| 브로드캐스팅 | 크기가 다른 텐서를 자동으로 맞춰 연산하는 기능 |
